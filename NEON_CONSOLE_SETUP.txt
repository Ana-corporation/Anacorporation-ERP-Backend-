PART 3: WHAT TO GET FROM NEON (COPY THESE)
================================================================================

Inside your project → click "Dashboard" or "Connect"

You need TWO connection strings:

  ┌─────────────────────────────────────────────────────────────────────┐
  │  1. POOLED connection (for running the NestJS app)                │
  │     Toggle: "Pooled connection" = ON                              │
  │     Label in UI: often shows "-pooler" in the hostname            │
  └─────────────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────────────┐
  │  2. DIRECT connection (for Prisma migrations)                     │
  │     Toggle: "Pooled connection" = OFF                             │
  │     Label in UI: hostname WITHOUT "-pooler"                       │
  └─────────────────────────────────────────────────────────────────────┘

Also copy / note these (safe to note):

  Item                    Where to find it
  -----------------------------------------------------------------------
  Project name            Top of project page (e.g. erp-backend)
  Database name           Usually "neondb" (in connection string)
  Region                  Project settings / dashboard
  Postgres version        Project settings (e.g. 16)

Example connection string shape (NOT real — replace with yours):

  postgresql://neondb_owner:ABC123xyz@ep-cool-name-123456-pooler.us-east-2.aws.neon.tech/neondb?sslmode=require
              ↑ user          ↑ password   ↑ host                                              ↑ database

WHERE TO PUT THEM IN YOUR ERP PROJECT:

  File: C:\ERP-Backend\.env

  DATABASE_URL="paste POOLED string here"
  DIRECT_DATABASE_URL="paste DIRECT string here"

PART 5: AFTER COPYING URLs — RUN THESE COMMANDS
================================================================================

Open terminal in C:\ERP-Backend:

  cd C:\ERP-Backend

  # 1. Install packages (if not done)
  npm install

  # 2. Paste URLs in .env first, then:
  npx prisma generate
  npx prisma migrate dev --name init
  npm run prisma:seed

  # 3. Start API
  npm run start:dev

Check:
  http://localhost:3000/docs
  http://localhost:3000/api/v1/health

PART 6: ADD ANOTHER DEVELOPER — TWO OPTIONS
================================================================================

Choose based on how much access they need:

  OPTION A — Full team member (recommended for permanent dev on your team)
  OPTION B — Project collaborator (good for freelancer / limited access)


--------------------------------------------------------------------------------
OPTION A — ADD ORGANIZATION MEMBER (full team access)
--------------------------------------------------------------------------------

Best for: Your co-founder, permanent backend developer, full team member.

What they get:
  - Access to ALL projects in your organization
  - Can see connection strings in Neon console
  - Can run migrations, view tables, create branches
  - Role: Admin or Member

STEPS:

  1. Go to: https://console.neon.tech/app/org-falling-dream-05010314

  2. In left sidebar, click "People" (or Organization → People)

  3. Click "Invite member"

  4. Enter developer's email (must be email they use for Neon signup)
     Example: dev@yourcompany.com

  5. Choose role:
       Admin  = can invite others, billing, delete projects
       Member = can use all projects, cannot change org billing/settings

  6. Click Send invite

  7. Developer receives email → creates Neon account (if new) → accepts invite

  8. They log in → see same projects under your organization

WHAT THE DEVELOPER DOES ON THEIR PC:

  1. Accept invite email
  2. Log into https://console.neon.tech
  3. Open project → Connection Details → copy their own connection strings
  4. Clone ERP repo: git clone ...
  5. Create .env with DATABASE_URL + DIRECT_DATABASE_URL
  6. npm install → prisma generate → migrate → start:dev

They do NOT need your password — they get access through Neon invite.


--------------------------------------------------------------------------------
OPTION B — ADD PROJECT COLLABORATOR (single project only)
--------------------------------------------------------------------------------

Best for: External freelancer, contractor, someone who only needs THIS database.

What they get:
  - Access to ONE project only (erp-backend)
  - Cannot delete the project
  - Project appears under "Shared with me" in their Neon account
  - Usage is billed to YOUR account

STEPS:

  1. Open your project (e.g. erp-backend)

  2. Click "Settings" (project settings, not org settings)

  3. Click "Collaborators" in the left sidebar

  4. Click "Invite"

  5. Enter developer email(s), comma-separated for multiple

  6. Click "Invite" to confirm

  7. Developer gets email → accepts → sees project as "Shared with me"

WHAT THE DEVELOPER DOES:

  Same as Option A — they copy connection strings from their own Neon console
  after accepting the invite.


--------------------------------------------------------------------------------
OPTION A vs OPTION B — QUICK CHOICE
--------------------------------------------------------------------------------

  Situation                              Use
  -----------------------------------------------------------------------
  Permanent team developer               Organization Member
  Co-founder / tech lead                 Organization Admin
  Freelancer for 2 months                Project Collaborator
  Only database access, not whole org    Project Collaborator


================================================================================
PART 7: WHAT DEVELOPERS SHARE IN THE TEAM (BEST PRACTICE)
================================================================================

DO share via team channel / repo:
  - Git repository access (GitHub/GitLab)
  - .env.example (template WITHOUT real passwords)
  - NEON_DATABASE_GUIDE.txt (this project's guide)
  - Redis setup instructions
  - API docs URL: http://localhost:3000/docs

DO NOT commit to Git:
  - .env file (real passwords)
  - gcp-service-account.json

Each developer creates their OWN .env locally with:
  - Same Neon project connection strings (if invited to Neon)
  OR
  - Their own Neon branch (advanced — optional for later)

Optional — Neon Branching (advanced, for later):
  Each dev can get a separate database branch from Neon for isolated testing.
  Not required for starting — one shared dev database is fine for small teams.
