1. WHAT WAS BUILT
--------------------------------------------------------------------------------

  Prisma schema : prisma/inventory/items.prisma
  Migration     : prisma/migrations/20260726120000_item_master/migration.sql
  Nest module   : src/modules/inventory/item-master/
  Registered in : src/app.module.ts  (InventoryMasterModule)

  Two tables:
    items                 — master header + general + classification + JSON bags
    item_warehouse_stock  — 1:N stock row per warehouse (Inventory tab grid)

  Design decision (same as Vendor):
    Fields that drive list filters / reports are REAL COLUMNS.
    Tab data that is only displayed on the form is stored in JSONB bags
    (purchase_json, sales_json, planning_json, production_json,
     properties_json, attachments_json, metadata).
    This means the FE can add tab fields WITHOUT a backend migration.

3. TABLE: item_warehouse_stock
--------------------------------------------------------------------------------

  DB column                  Type            API field             Req  Default
  -------------------------  --------------  --------------------  ---  -------
  item_warehouse_stock_id    BIGSERIAL PK    itemWarehouseStockId  -    auto
  company_id                 BIGINT FK       (from URL)            yes  -
  item_id                    BIGINT FK       (from URL)            yes  -
  warehouse_id               BIGINT FK       warehouseId (string)  YES  -
  is_locked                  BOOLEAN         isLocked              no   false
  qty_on_hand                DECIMAL(18,6)   qtyOnHand             no   0
  qty_committed              DECIMAL(18,6)   qtyCommitted          no   0
  qty_ordered                DECIMAL(18,6)   qtyOrdered            no   0
  required_qty               DECIMAL(18,6)   requiredQty           no   null
  minimum_qty                DECIMAL(18,6)   minimumQty            no   null
  maximum_qty                DECIMAL(18,6)   maximumQty            no   null
  first_bin_location         VARCHAR(80)     firstBinLocation      no   null
  default_bin_location       VARCHAR(80)     defaultBinLocation    no   null
  enforce_default_bin        BOOLEAN         enforceDefaultBin     no   false
  created_by / created_at / updated_by / updated_at / row_version

  Constraints:
    UNIQUE (item_id, warehouse_id)
    FK item_id      -> items(item_id)           ON DELETE CASCADE
    FK warehouse_id -> warehouses(warehouse_id) ON DELETE CASCADE

  NOTE: "Available" is NOT stored. Compute on FE:
        available = qtyOnHand - qtyCommitted


4. ENUM-LIKE VALUES (validated by backend)
--------------------------------------------------------------------------------

  itemType         : item | service | labor | travel
  manageBy         : none | serial | batch
  status           : active | inactive | advanced
  valuationMethod  : moving_average | standard | fifo | serial_batch

  Sending anything else returns 400 with a Zod validation error.


5. API ENDPOINTS
--------------------------------------------------------------------------------

  Base: /api/v1/companies/{companyId}/items
  Auth: Bearer JWT. Permission module 'supply-chain' (same as Vendors):
        view -> GET, create -> POST, edit -> PATCH/PUT, delete -> DELETE

  GET    /companies/{companyId}/items                     list (paginated)
  GET    /companies/{companyId}/items/{id}                one + warehouse stock
  POST   /companies/{companyId}/items                     create
  PATCH  /companies/{companyId}/items/{id}                partial update
  DELETE /companies/{companyId}/items/{id}                soft delete
  PUT    /companies/{companyId}/items/{id}/warehouses     upsert one stock row
  DELETE /companies/{companyId}/items/{id}/warehouses/{warehouseId}

  LIST query params:
    page, limit, sortBy, sortOrder, search, fromDate, toDate
    code            (contains, item_code)
    description     (contains)
    brandName       (contains)
    status          (exact)
    itemType        (exact)
    itemGroup       (exact)
    division        (exact)
    majorGroup      (exact)
    isActive / isInventoryItem / isSalesItem / isPurchaseItem  (boolean)

    search hits: itemCode, description, oldCode, barcode, brandName
    sortBy allow-list: itemCode | description | status | createdAt (default createdAt)

9. FE TAB MAPPING
--------------------------------------------------------------------------------

  Header (always visible)
    itemCode, description, oldCode, itemType, itemGroup, uomGroup,
    barcode, priceList, unitPrice + currencyCode,
    isInventoryItem / isSalesItem / isPurchaseItem

  general      -> doNotApplyDiscountGroups, manufacturer, additionalIdentifier,
                  shippingType, manageBy, status, activeFrom, activeTo
  purchasing   -> preferredVendorId (column) + purchase{} bag
  sales        -> sales{} bag
  inventory    -> valuationMethod, itemCost, manageStockByWarehouse (columns)
                  + inventory{} bag + warehouse grid (separate endpoint)
  planning     -> planning{} bag
  production   -> production{} bag
  properties   -> properties{} bag (map of code -> boolean, NOT 64 columns)
  remarks      -> remarks (TEXT)
  attachments  -> attachments[] bag (real file storage lands in a later phase)

  Right panel (put under general or its own "classification" section)
    netWeightKg, grossWeightKg, division, coreActivity, majorGroup,
    brandName, effectiveDate, customerStockNo, stockToBe, stockDioDays,
    contractItemsFor


10. ERRORS TO EXPECT
--------------------------------------------------------------------------------

  400  Zod validation (bad enum, string too long, non-numeric id)
  404  Item / Warehouse / Preferred vendor not found in this company
  409  "Item code already exists"  (unique per company, case-insensitive
       because codes are uppercased on save)
