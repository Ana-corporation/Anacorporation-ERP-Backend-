1. DECISIONS ALREADY TAKEN
--------------------------
D1  Stock "At Vendor" = a normal Inventory Location under the company's
    "Sub Contractor Store" store category, one location per vendor.
    New nullable warehouses.vendor_id links the location to Vendor Master.
    Stock there stays company-owned; no purchase / payable is created.
D2  Stock is still counted by item + location (warehouse) + bin.
    NO new stock dimensions in Phase 1 (no vendor / status / batch / serial
    in stock_balances or stock_ledger_entries).
D3  QC Hold / In Process / batch-wise and serial-wise balances = Phase 2.
D4  Opening Stock never creates SF / FF (or any non-eligible) items.
    Eligibility is a per-category setting, not a hard-coded list.
D5  Item Master has no revision field: Revision stays a line-level text.

4. RULES TO IMPLEMENT (all on the backend; frontend checks are only help)
------------------------------------------------------------------------
R1  Header default store
    default_warehouse_id saved on the document. Lines still carry their own
    warehouse_id (the source of truth). Must be an active location the user
    may access.

R2  Totals
    line_total = quantity x unit_price (Decimal, 6 dp) computed on save AND
    re-computed on post. Header totals = sum of lines. Ignore any totals the
    client sends.

R3  Unit price
    For OPENING_STOCK lines: unit price missing or 0 -> allowed only when the
    line has zero_price_confirmed = true. Posting a document with confirmed
    zero-price lines requires opening_stock:approve.
    Error: OPENING_STOCK_ZERO_PRICE (field lines[i].unitPrice).

R4  Batch / serial (driven by items.manage_by, not by category)
    manage_by = batch  -> batch_no required.
    manage_by = serial -> serial_no required, quantity must be 1, serial
                          unique per company + item across POSTED opening
                          lines and within the document.
    manage_by = none   -> batch / serial optional (stored as reference).
    Errors: BATCH_REQUIRED, SERIAL_REQUIRED, SERIAL_QTY_ONE, SERIAL_DUPLICATE.

R5  Duplicate lines in one document
    Keep existing check (item + location + bin). Extend the key with
    batch_no and serial_no when the item is batch / serial managed.
    Error: INVENTORY_DUPLICATE_LINE (existing).

R6  Second opening stock (on POST, after balance locks are taken)
    Block when a POSTED OPENING_STOCK line already exists for the same
    company + item + warehouse + bin (+ batch_no / serial_no when managed).
    Error: OPENING_STOCK_ALREADY_EXISTS with the existing document number.
    Corrections go through Stock Adjustment.

R7  Backdated transactions
    On POST of MATERIAL_ISSUE and STOCK_ADJUSTMENT: for each line, if a
    posted OPENING_STOCK exists for item + warehouse + bin with
    document_date > this document_date -> reject.
    Error: TRANSACTION_BEFORE_OPENING_STOCK (shows the opening date).
    Opening Stock itself: reject if a later-dated non-opening movement
    already exists for that key with an earlier date than the OS date.
    Keep document_date and posted_at separate (already the case).

R8  Bin validation (existing - re-check on post)
    bin_management location -> bin required, bin belongs to that location,
    bin active. Non-bin location -> no bin. Already in the line resolver;
    make sure post re-runs it (it does today - keep).

R9  Vendor locations (D1)
    If the line's warehouse has vendor_id -> that vendor must exist in the
    company and be active at save and at post. Error: VENDOR_INACTIVE.
    Warehouse create/update API accepts vendorId (optional, active vendor).
    Current Stock list returns warehouse.vendor { vendorId, name } so the
    UI can show "At vendor: ...". Filter ?vendorId= on current stock.

R10 Attachments
    POST   /inventory/opening-stock/:id/attachments        (multipart; draft or posted)
    GET    /inventory/opening-stock/:id/attachments/:fileAssetId/url
    DELETE /inventory/opening-stock/:id/attachments/:fileAssetId  (draft only)
    Reuse the item-attachment code path (StorageService + file_assets);
    same size / type limits.

R11 Save & Post
    No new endpoint: client calls POST (or PUT) then POST :id/post.
    Post must stay idempotent by the existing DRAFT claim (second call ->
    INVENTORY_DOCUMENT_ALREADY_POSTED).

R12 Audit
    Keep user_audit rows (create / update / post / delete). Document detail
    returns createdBy/At, updatedBy/At, postedBy/At (names via withAudit),
    plus importBatch { batchId, fileName, approvedBy, approvedAt,
    createdItemCount } when the document came from an import.


5. EXCEL IMPORT CHANGES
-----------------------
I1  Template columns (OPENING_IMPORT_COLUMNS), in this order:
      Category Code*, Part Number, Part Name, Store (Location Code)*, Bin,
      Qty*, Unit Price, Inventory UOM, Batch / Heat / Lot No., Serial No.,
      Revision, Remarks,
      reference: Part Code, Material Grade, Size, Revision Status,
      Machine Model, Machine No, Category
    Location rule (write in the template "Instructions" sheet):
      "Store (Location Code)" = Inventory Location code only.
      "Bin" = bin code inside that location.
      Legacy "CODE/BIN" in the location cell is still accepted.
    Add an "Instructions" sheet describing every column.

I2  Matching (MATCHED)
    Part Number found, item active, Category Code = item's category, store /
    bin valid, qty > 0, price valid. Part Name and UOM always taken from the
    Item Master (Excel values only used for NEW rows / warnings).
    Wrong Category Code for an existing part -> ERROR "Category Code X does
    not match item category Y".

I3  NEW rows
    - Category must have item_groups.allow_opening_create = true, else ERROR
      "New items are not allowed in category X" (covers SF / FF - D4).
    - similar_items: up to 3 existing items in the same company with a
      similar name (normalised tokens / trigram-like score >= 0.6), computed
      on upload and on validate. Shown as a duplicate warning.
    - new_item_confirmed must be true before approve.
      POST /opening-stock-imports/:id/rows/confirm-new  { rowIds?: [] }
           (no rowIds = confirm all NEW rows)  perm: opening_stock:approve
      POST /opening-stock-imports/:id/rows/exclude      { rowIds: [], excluded: bool }
    - Picking an existing item for a NEW row (existing row edit) turns it
      into MATCHED.

I4  ERROR rows (add to existing checks)
    missing mandatory, wrong category, unknown / inactive store, invalid
    bin, bad UOM, bad qty / price, duplicate rows (same key as R5),
    ineligible category, serial / batch rules (R4), zero price without
    confirmation is a WARNING on the row (not an error) and is confirmed on
    approve with the same zero_price_confirmed flag.

I5  Approve (existing endpoint)
    canApprove = no unconfirmed NEW rows (except excluded) and >= 1 stock
    row. Re-evaluate every row inside the transaction, then: create
    confirmed NEW items (Item Master service), post one OPENING_STOCK with
    R2-R9 applied. Excluded + ERROR rows skipped. Already idempotent
    (batch locked after APPROVED, file-hash check) - keep.
    Body: { confirmZeroPrice: boolean } (needed when zero-price rows exist).

I6  Error report (existing endpoint) - one line per error:
      Original Row No | Part Number | Column | Error Reason | Suggested Correction
    Suggestions where possible (e.g. "Use bin code A-01 of RMS-001",
    "Category of ANARM00012 is RM").
