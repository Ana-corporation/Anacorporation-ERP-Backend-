  ITEM (prisma/inventory/items.prisma)
  ------------------------------------

  --------------------  --------------------------------------------------
  itemCode              Optional; required only if company itemCodeMode=MANUAL
                        AUTO mode ignores client code → ITM-######
  description           REQUIRED
  itemType              item|service|labor|travel
  itemGroup             free-text (NOT category ID)
  uomGroup              free-text (NOT unit ID)

  Unique: @@unique([companyId, itemCode]) — includes soft-deleted rows
  NO Category / Unit lookup tables — names are free-text strings
  preferredVendorId = numeric string vendor ID (company-scoped)


  OPENING STOCK (ItemWarehouseStock)

  --------------------  --------------------------------------------------

  warehouseId           FK → Warehouse (resolve by warehouseCode)
  qtyOnHand             Decimal — CURRENTLY direct overwrite via upsert

  NO Location master table
  NO stock transaction / ledger model in live schema

8. RISKS / CONFLICTS / DECISIONS
--------------------------------------------------------------------------------

  D1  Vendor codes are AUTO-ONLY today.
      Decision for V1: Excel must NOT supply vendorCode.
      Template requires Supplier Type + Name; BE generates RM001 etc.
      Duplicate check = duplicate NAME in file (warn) + DB unique on code (auto).
      If product needs imported supplier codes → needs MANUAL vendor code mode (out of V1 unless asked).

  D2  Item codes depend on company itemCodeMode.
      Decision: Template includes Item Code column.
      AUTO company → ignore Excel code, auto-generate.
      MANUAL company → Item Code required; duplicate = ERROR.

  D3  No Category/Unit masters.
      Decision: Item Group / UOM Group are free-text columns (match schema).
      Do NOT invent categoryId/unitId resolution.

  D4  Opening stock has NO ledger.
      Decision V1: use existing upsertWarehouseStock (direct qtyOnHand write).
      Document as OVERWRITE semantics (re-import replaces qty).
      Permission: items:edit (existing).
      Location = free-text bin column, not FK.
      Building a full stock ledger = separate project.

  D5  Session storage.
      Decision V1: rows_json on import_sessions (≤5k rows OK).
      File: parse in memory → discard (or optional GCS via StorageService).
      Do NOT keep files on local disk.

  D6  Soft-delete unique collision.
      Deleted vendor/item codes still block reuse (P2002).
      Import must treat unique violation as DUPLICATE_* error.

  D7  Vendor sequence max 999 per prefix.
      Large imports of same supplierType may fail late sequences.

  D8  Dead inventory/products modules — never wire import to them.
