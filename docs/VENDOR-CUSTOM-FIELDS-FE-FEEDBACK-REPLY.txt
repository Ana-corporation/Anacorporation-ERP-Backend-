2. SHOULD (confirmed + fixed where needed)
--------------------------------------------------------------------------------

SHOULD-1  Clear values on PATCH
  FIXED to FE preferred:
    omit key     → leave existing
    key: null    → clear (delete value row) if not required
    key: ""      → clear text-like fields if not required
    checkbox false → store false
    clear required field → 400

SHOULD-2  Required on UPDATE when key omitted
  CONFIRMED: yes — omitted keys are NOT re-validated on update.
  Only included keys are upserted/cleared.
  Required check applies on create, or when a required key is sent empty.

SHOULD-3  defaultValue types
  CONFIRMED:
    text/textarea/email/phone/date/dropdown → string | null
    number/decimal → number | null
    checkbox → boolean | null (treat null as false in FE)

SHOULD-4  Error payload shape
  FIXED — now includes errors[] with field paths.
  Example 400 (unknown key):

  {
    "success": false,
    "message": "Unknown custom field: fooBar",
    "data": null,
    "errors": [
      { "field": "customFields.fooBar", "message": "Unknown custom field: fooBar" }
    ],
    "timestamp": "2026-07-22T...",
    "path": "/api/v1/companies/2/vendors"
  }

  Example 400 (required):

  {
    "success": false,
    "message": "Custom field \"Payment Terms\" is required",
    "data": null,
    "errors": [
      {
        "field": "customFields.paymentTerms",
        "message": "Custom field \"Payment Terms\" is required"
      }
    ],
    "timestamp": "...",
    "path": "..."
  }
