1. GLOBAL SAAS RULES  [REQUIRED]
--------------------------------
- No India-only fields in shared screens. Use generic labels with the
  country value: "Tax ID" (type GSTIN / PAN / VAT ...), "Region"
  (State in India), "Postal code" (PIN in India).
- Money: format with the currency decimal_places returned by the API
  (JPY 0, INR / USD 2, KWD 3) and the company locale (Intl.NumberFormat).
  Never hard-code 2 decimals or the Rs symbol.
- Dates: show in the company timezone and locale (Intl.DateTimeFormat).
  valid_until is a date only (no time).
- Error text: map error codes to text in the FE (one messages file per
  language; English now). Do not show raw server messages to users when a
  code mapping exists.
- Tax: show the tax_breakdown list from the API (name, rate, amount).
  Never build CGST / SGST / IGST labels in the FE.


2. RULES  [REQUIRED]
--------------------
- Never calculate final totals in the browser. Show totals from the API
  (preview-totals while editing, saved totals after save).
- Always send rowVersion on update / actions. On 409 ROW_VERSION_CONFLICT show
  "This quotation was changed by someone else. Reload?" and reload.
- Show buttons from allowedActions[] returned by the API (server still checks).
- Show field errors next to the field (path like "lines[0].quantity"), plus a
  summary at the top. Keep user input on error.
- Confirm dialog before Issue, Cancel, Reject.
- Unsaved-change warning when leaving the editor.
- Lists: S.No column, scroll loading (50 per page), server search / filters.
- Hide margin columns unless the user has sales_quotations:view_margin.
- [CHANGED] Idempotency-Key on EVERY state-changing action: Issue, Record
  response, Cancel and Send-email.
    * Create one UUID per button click and send it in the Idempotency-Key
      header.
    * Retry of the SAME click (network error, timeout) reuses that key.
    * A new click creates a new key.
    * Disable the button while the request is running.
    * On IDEMPOTENCY_KEY_REUSED with a different payload, show the mapped
      message and ask the user to reload.
- [CHANGED] Show the "Expired" state from isExpired in the API list and
  detail responses, never from a browser date check. Expired Sent
  quotations cannot be recorded as Accepted (button disabled; the server
  also blocks it with QUOTATION_EXPIRED).
- [CHANGED] Never compute a base-currency total in the browser. Show it only
  when the API returns grand_total_base.

6. PHASE 1 - MASTERS
--------------------
6.1 [REQUIRED] Customer list   API GET companies/:companyId/customers
  Columns: S.No, Code, Name, Primary tax ID, Country, City, Phone, Email,
  Salesperson, Active.
  [CHANGED] [DEPENDS] Primary tax ID and city come from the list response
  (backend returns primary_tax_id and primary_city). Do NOT make one extra
  call per row.
  Search (code, name, email, phone, tax id). Filters: Active, Type,
  Salesperson, Country. Scroll loading. Row actions: View, Edit, Delete.

6.2 [REQUIRED] Customer form   API POST / PATCH /customers(/:id)
  Tab General : Name*, Legal name, Type, Code (auto, read-only), Country*,
                Currency*, Language, Email, Phone, Website, Payment terms,
                Salesperson, Credit limit, Active*, Notes.
  Tab Tax IDs : rows of Type (GSTIN, PAN, VAT, EIN, ABN, Other), Value,
                Country, Primary.
                [CHANGED] [DEPENDS] "Fetch details" button next to a value
                calls POST /customers/registration-lookup (India GSTIN works
                first) and fills name + address. Hide the button for ID
                types with no lookup provider.
  Tab Addresses: rows of Bill-To / Ship-To with Line 1, Line 2, City,
                 Region, Postal code, Country*. At least one Bill-To*.
                 Region is required when the country needs it (India yes;
                 API returns REGION_REQUIRED). Default per type.
  Tab Contacts : Name, Designation, Email, Phone, Primary.
  (* = required. Error codes: CUSTOMER_NAME_REQUIRED, BILL_TO_REQUIRED,
     COUNTRY_REQUIRED, REGION_REQUIRED, CUSTOMER_CODE_EXISTS,
     CUSTOMER_IN_USE, TAX_ID_INVALID, TAX_ID_DUPLICATE.)
  [LATER] Anonymize customer action (privacy erase, needs permission,
          confirm dialog).

6.3 [REQUIRED] Payment Terms   list + add / edit dialog
  Fields: Code, Name, Days, Description, Active.

6.4 [REQUIRED] Number Series screen
  For SALES_QUOTATION and CUSTOMER: Prefix, Pattern (tokens {PREFIX} {FY}
  {YYYY} {MM} {SEQ}), Separator, Serial length, Start from, Reset
  (Never / Yearly / Fiscal year).
  [CHANGED] [DEPENDS] Live preview ("QT/2026-27/0001") comes from the
  backend preview endpoint, which does NOT consume a number. The endpoint
  already exists (GET number-series/:documentType/preview); the backend
  extends it for pattern series. Do not build the preview in the browser.
  Call it (debounced) when any field changes.
  ITEM series screen stays as it is.

6.5 [LATER] Delivery Terms (Code, Name, Incoterm, Description, Active) and
  T&C Templates (Name, Language, Body, Default, Active) - list + dialog.


7. PHASE 2 - QUOTATION LIST + EDITOR
------------------------------------
7.1 [REQUIRED] Quotation list   API GET /sales/quotations
  Columns: S.No, Quotation No, Version, Date, Customer, Salesperson,
           Valid Until, Status chip, Currency, Grand Total.
  Search: number, customer, customer reference.
  Filters: Status, Customer, Salesperson, Date range.
  Row actions from allowedActions: Open, Edit, Copy, Delete (draft only).
  [CHANGED] Show the "Expired" chip when the API field isExpired = true.

7.2 [REQUIRED] Quotation editor   API POST / PATCH /sales/quotations(/:id)
  Top bar: Quotation No + Version + Status chip; buttons from allowedActions
           (Save, Submit, Issue, Print, Copy, Cancel ...).
  Header panel
    Customer* (search select, API /customers/lookup). On select, fill
    currency, payment terms, bill-to, ship-to, contact from customer
    defaults (user can change).
    Contact, Bill-To, Ship-To, Customer reference, Quotation date*,
    Valid until*, Salesperson, Currency*, Payment terms, Delivery terms
    (text until the master exists, keep it editable).
    [CHANGED] [DEPENDS] Valid until default: the backend returns it in the
    new-quotation defaults response (company setting, 30 days). The FE only
    displays it; it does not add 30 days itself.
    [CHANGED] [DEPENDS] Exchange rate: shown only when currency is not the
    base currency. Editable only with sales_quotations:override_exchange_rate,
    otherwise read-only.
    Badge: "Prices exclude tax" / "Prices include tax" (from the quotation).
  Line grid (keyboard friendly: Enter = next cell, add row at end)
    [REQUIRED] Item* (search by code / name), Description (from item,
               editable), Qty*, UOM*, Unit price*, Disc %, Line net
               (from API).
    [LATER]    Add Section / Text / Optional line buttons;
               Customer part no, Delivery date, Remarks columns;
               Unit cost, Margin % columns (view_margin only).
  [LATER] Charges block: Freight, Packing, Insurance, Other.
  Totals panel (always visible, sticky)
    Subtotal, Line discounts, Document discount, Charges, then one row per
    tax_breakdown entry (empty until Phase 7), Round-off, Grand total.
    [CHANGED] "Grand total in base currency" row only when the currency
    differs from the base currency and the API returns grand_total_base
    (backend plan includes it).
    Values from POST /preview-totals, called on change (~400 ms debounce).
  Tabs
    [REQUIRED] Terms (text box), Customer notes, Internal notes
               (label: "Not printed").
    [IF ANA]   Attachments (drawings, datasheets).
    [LATER]    Pick T&C template, History.
