-------

returns small signed token + permission snapshot for UI sessionStorage.


================================================================================
HIGH-LEVEL FLOW (REFERENCE)
================================================================================

  UI -> POST /api/v1/auth/login { username, password, companyId? }
  Server -> Validate user + password
  Server -> Load memberships, roles, subscription, modules, permissions
  Server -> Create session / issue refresh token
  Server -> Return accessToken + user + companies + activeCompany + permissions
  UI -> Store token + permission snapshot (sessionStorage)
  UI -> Redirect to /company/{companyId}/dashboard

RULES:
  - Server decides access (DB queries + business rules)
  - Client only stores what UI needs (token + cached permission map)
  - Every API call re-validates token; do NOT trust sessionStorage alone

CLIENT STORAGE GUIDE (FOR FRONTEND REFERENCE)
================================================================================

STORE IN sessionStorage (UI cache only):
  - accessToken
  - authContext: { user, activeCompanyId, companies, modules, role, subscriptionStatus }

DO NOT STORE:
  - password hash
  - refresh token in sessionStorage if XSS risk (prefer httpOnly cookie)

BETTER SPLIT:
  accessToken        -> memory or sessionStorage (short-lived)
  refreshToken       -> httpOnly secure cookie
  permission snapshot-> sessionStorage (for menu/gates)

SQL JOIN SKETCH (ONE COMPANY CONTEXT)
================================================================================

-- 1) membership
SELECT * FROM user_companies
WHERE user_id = ? AND company_id = ? AND status = 'active';

-- 2) subscription
SELECT cs.*, sp.plan_code, sp.name
FROM company_subscriptions cs
JOIN subscription_plans sp ON sp.plan_id = cs.plan_id
WHERE cs.company_id = ? AND cs.status = 'active'
  AND (cs.end_date IS NULL OR cs.end_date >= CURRENT_DATE)
LIMIT 1;

-- 3) entitled modules (plan)
SELECT m.module_id, m.module_code, m.module_name, cm.is_active
FROM plan_modules pm
JOIN modules m ON m.module_id = pm.module_id
LEFT JOIN company_modules cm
  ON cm.company_id = ? AND cm.module_id = m.module_id
WHERE pm.plan_id = ?;

-- 4) role
SELECT r.role_id, r.role_code, r.role_name
FROM user_roles ur
JOIN roles r ON r.role_id = ur.role_id
WHERE ur.user_id = ? AND ur.company_id = ? AND ur.is_active = true;

-- 5) permissions
SELECT m.module_code, p.action
FROM role_permissions rp
JOIN permissions p ON p.permission_id = rp.permission_id
JOIN modules m ON m.module_id = p.module_id
WHERE rp.role_id = ? AND rp.is_allowed = true;

-- 6) overrides
SELECT m.module_code, uma.access_type
FROM user_module_access uma
JOIN modules m ON m.module_id = uma.module_id
WHERE uma.user_id = ? AND uma.company_id = ?;

Server merges (3) + (5) + (6) -> final module permission map.
