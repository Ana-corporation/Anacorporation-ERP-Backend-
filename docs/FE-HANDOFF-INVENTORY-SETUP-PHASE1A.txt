2) INVENTORY LOCATIONS — WAREHOUSES (EXTENDED)
================================================================================

  FE maps: Inventory Location = Warehouse

  Paths (unchanged):

    GET    /companies/{companyId}/warehouses
    GET    /companies/{companyId}/warehouses/{warehouseId}
    POST   /companies/{companyId}/warehouses
    PATCH  /companies/{companyId}/warehouses/{warehouseId}
    DELETE /companies/{companyId}/warehouses/{warehouseId}

  Permissions:
    warehouses:view | warehouses:create | warehouses:edit | warehouses:delete

  --------------------------------------------------
  NEW FIELDS (persist + echo on list/detail/create/update)
  --------------------------------------------------

    locationType     string enum:
                       "Warehouse" | "Store" | "Godown" | "Other"
                       default on create if omitted: "Store"
    binManagement    boolean  default false
    isDefault        boolean  default false
                       at most ONE default per company
                       (setting true clears previous company default)

  Create body FE should send:

    {
      "warehouseCode": "LOC001",
      "name": "Main Warehouse",
      "branchId": "2",
      "address": "optional",
      "isActive": true,
      "locationType": "Warehouse",
      "binManagement": true,
      "isDefault": false
    }

  Update body (partial OK):

    {
      "name": "Main Warehouse",
      "branchId": "2",
      "address": "...",
      "isActive": true,
      "locationType": "Store",
      "binManagement": false,
      "isDefault": true
    }

  Notes:
    - branchId REQUIRED on create (same company)
    - warehouseCode UNIQUE within company (uppercased by BE)
    - warehouseCode is NOT updatable via PATCH (immutable today)
    - List is paginated: { items, total, page, limit, totalPages }

  Example response row:

    {
      "warehouseId": "5",
      "companyId": "10",
      "branchId": "2",
      "warehouseCode": "LOC001",
      "name": "Main Warehouse",
      "address": "...",
      "isActive": true,
      "locationType": "Warehouse",
      "binManagement": true,
      "isDefault": false
    }

  FE action:
    Remove client-side overlay for locationType / binManagement / isDefault.
    Trust API response.

3) STORAGE BINS — NEW API
================================================================================

  Paths:

    GET    /companies/{companyId}/storage-bins
    GET    /companies/{companyId}/storage-bins/{storageBinId}
    POST   /companies/{companyId}/storage-bins
    PATCH  /companies/{companyId}/storage-bins/{storageBinId}
    DELETE /companies/{companyId}/storage-bins/{storageBinId}

  Optional list filters:

    GET .../storage-bins?inventoryLocationId={id}
    GET .../storage-bins?warehouseId={id}

    (inventoryLocationId === warehouseId; either works)

  Permissions (Phase 1A Option A — matches FE today):

    warehouses:view   → list / get
    warehouses:create → create
    warehouses:edit   → update
    warehouses:delete → delete

  Create body (send either or both location keys):

    {
      "inventoryLocationId": "5",
      "warehouseId": "5",
      "binCode": "GOD-01-04-03",
      "binName": "Rack 01 - Shelf 04 - Position 03",
      "isActive": true
    }

  Update body (partial):

    {
      "binCode": "GOD-01-04-03",
      "binName": "Rack 01 - Shelf 04 - Position 03",
      "isActive": true
    }

  Response row (always includes BOTH id aliases):

    {
      "storageBinId": "11",
      "companyId": "10",
      "inventoryLocationId": "5",
      "warehouseId": "5",
      "binCode": "GOD-01-04-03",
      "binName": "Rack 01 - Shelf 04 - Position 03",
      "isActive": true
    }

  Rules:
    1. Parent warehouse must exist in same company
    2. Parent must have binManagement = true  else 400 BIN_MANAGEMENT_DISABLED
    3. Parent must be active                 else 400 LOCATION_INACTIVE
    4. binCode UNIQUE within inventory location (uppercased by BE)
    5. Soft delete via DELETE
    6. Block delete when stock qty > 0       → later (Phase 1B+)

  FE action:
    Stop localStorage fallback when these endpoints return 200.
