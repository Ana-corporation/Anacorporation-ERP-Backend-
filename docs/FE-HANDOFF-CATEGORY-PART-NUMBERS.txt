0) IN ONE MINUTE

  Part number was   ANA + STORE code    + serial   → ANABO00001

                                                     ANARM00001 (Raw Materials), ANAASSY00001 ...
  - Category master = the existing Item Group master + a Category Code (2-4 letters) +
    Description (examples / scope). Each category belongs to one Store.
  - Number Series "Segment source" now has: Category (Item Group) | Store | None.
    ANA uses Category. Every category has its own counter.
  - Item form: Store → Category (filtered by Store) → Part Number ... Both mandatory.
    After the first save Store and Category are locked.
  - Opening Stock import: new column "Category Code" (BRG, PLY ...). Store comes from it.
  - Other companies: nothing changes unless their admin picks "Category" in Number Series.


1) CATEGORY MASTER SCREEN (Item Groups API — same routes as before)
--------------------------------------------------------------------------------
  Menu label for ANA: "Category Master". Columns: Store | Category Code | Category | Examples / Scope
    | Items | Active.
  GET /api/v1/companies/:companyId/item-groups?storeCategoryId=&includeInactive=
    new keys per row:
      categoryCode            "BRG" | null
      description             "Ball bearings, roller bearings" | null
      effectiveCategoryCode   own code, or the nearest parent's (sub-groups) — use it in pickers
      codeLocked              true = part numbers already use this code → make the code read-only
  POST  { name, storeCategoryId, categoryCode?, description?, parentId?, sortOrder?, isActive? }
  PATCH /:id { name?, categoryCode?, description?, sortOrder?, isActive?, parentId? }
    categoryCode: 2-4 letters, sent in any case (backend uppercases); "" or null = no code.
  Errors:
    ITEM_GROUP_CODE_EXISTS   409  another category already uses the code (unique per company)
    ITEM_GROUP_CODE_LOCKED   400  code used by part numbers — cannot change / remove
    ITEM_GROUP_CODE_INVALID  400  not 2-4 letters
  Sub-groups (optional): a sub-group without a code numbers with its parent's code
  ("Ball Bearings" under Bearings → ANABRG...). Show effectiveCategoryCode in grey.
  Saving a code also creates / updates the category's line in Number Series (no extra call).


2) NUMBER SERIES SETTINGS
--------------------------------------------------------------------------------
  Segment source dropdown: "Category (Item Group)" = ITEM_GROUP | "Store" = STORE | "None" = NONE
  (ITEM_GROUP is no longer rejected.)
  GET /number-series/ITEM with segmentSource = ITEM_GROUP:
    lines = one row per category that has a code:
      { numberSeriesLineId, segmentRefId (= itemGroupId), segmentName (category),
        storeCategoryId, storeName, segmentCode (= category code, READ-ONLY here),
        startFrom, serialLength, lastNumber, isLocked, nextNumber }
    Table columns: Category | Store | Segment Code | Start From | Serial Length | Last Number Used
    Live preview: "Next number for Bearings: ANABRG00001" (line.nextNumber or
      GET /number-series/ITEM/preview?segmentRefId=<itemGroupId>).
  PUT /number-series/ITEM  lines: [{ segmentRefId: <itemGroupId>, startFrom?, serialLength? }]
    segmentCode is ignored (edit it in the Category master). Lines for coded categories not
    sent are created with defaults. Switching source (only while unlocked) rebuilds the lines.
  Locks (unchanged rules): after the first number → prefix, segment source, separator, serial
    length and the category codes are locked; Start From can only go up, above Last Number Used.
  New field on every line (all sources): storeCategoryId, storeName.


3) ITEM FORM
--------------------------------------------------------------------------------
  ANA order (from form-schema): Store* → Category* → Part Number → Part Name* → Inventory Item
    | Inventory UOM* → Status | Remarks | Attachments.
  The Category field (fieldKey itemGroupId, now in the header section) — options:
    GET /item-groups/tree?storeCategoryId=<store>   (show "BRG — Bearings")
  Changing Store clears Category. Part Number shows "Auto-generated on save" and, after a
  Category is picked, optionally the preview (number_series:view; ignore 403).
  After first save: Store and Category read-only, tooltip "Part number is based on the category".
  Errors:
    ITEM_STORE_REQUIRED       400  storeCategoryId
    ITEM_CATEGORY_REQUIRED    400  itemGroupId (Category-based series)
    ITEM_GROUP_STORE_MISMATCH 400  category of another store
    NUMBER_SERIES_NOT_CONFIGURED 400 field itemGroupId — category has no code / no series line
    ITEM_CATEGORY_LOCKED      400  category change after first save
    ITEM_STORE_LOCKED         400  store change after first save


4) OPENING STOCK IMPORT
--------------------------------------------------------------------------------
  Template columns: Store, Category Code, Part Number, Part Name, ... (Category Code is new).
  Category-based companies: "Category Code" column is required; Store is optional (if filled it
  must match the category's store).
  New items get Store + Category from the code, so the "Set Item Group" step is not needed
  (newRowsWithoutGroup stays 0). Rows show data.categoryCode and itemGroupId.
  Row errors (field categoryCode): unknown code, category inactive, code missing on a new item,
  category without a Number Series line. Valid rows still post. Approve = one transaction.
