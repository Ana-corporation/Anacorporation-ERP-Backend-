5. API CHEAT SHEET (ADMIN DIRECT)
--------------------------------------------------------------------------------

  Meta
    GET  /api/v1/custom-fields/meta/modules
    GET  /api/v1/custom-fields/meta/modules/vendor/sections

  Create (immediate — no PENDING)
    POST /api/v1/companies/{companyId}/custom-fields
    {
      "entityType": "vendor",
      "sectionKey": "general",
      "displayName": "Factory Capacity",
      "fieldType": "number",
      "isRequired": false,
      "sortOrder": 40,
      "validation": { "min": 0, "max": 100000 }
    }

  List
    GET  /api/v1/companies/{companyId}/custom-fields?entityType=vendor
    GET  ...?entityType=vendor&groupedBySection=true

  Update / Deactivate
    PATCH  .../custom-fields/{fieldId}
    DELETE .../custom-fields/{fieldId}

  Vendor form
    GET  .../entities/vendor/form-schema
    POST .../vendors  { ..., "customFields": { "factoryCapacity": 250 } }
    GET  .../vendors/{id}  → includes customFields map


6. PERMISSIONS (NO request / approve)
--------------------------------------------------------------------------------

  custom_fields:view     list / get definitions + meta
  custom_fields:create   create definition NOW
  custom_fields:edit     update definition
  custom_fields:delete   soft deactivate

  supply-chain:view      load form-schema + see vendor
  supply-chain:create    create vendor with customFields
  supply-chain:edit      update vendor customFields

  NOT used (skipped by product decision):
    custom_fields:request
    custom_fields:approve


7. WHAT WAS CHANGED vs APPROVAL SPEC
--------------------------------------------------------------------------------

  Spec said: Request → Pending → Approve → definition
  We do:     Admin Create → definition ACTIVE immediately

  APIs already existed for admin create — kept / documented.
  No custom_field_requests table.
  No approval endpoints.
