Q5 + Q17 — MODULE NAMESPACE (PRODUCT vs ADMIN)              [LOCKED + BE-TODO]
================================================================================
  DECISION: activeCompany.modules[] returns PRODUCT modules ONLY.
    product module codes (Phase 1 target):
      financials, supply-chain, hcm, manufacturing, crm, projects

  ADMIN areas (iam, organization, subscription, shared) are:
    - NOT subscription-gated
    - NOT returned in modules[]
    - authorized by ROLE (role_permissions) only

  BACKEND REALITY (important):
    There is ONE physical `modules` table. permissions, plan_modules,
    company_modules, role_permissions, user_module_access ALL reference it.
    So "product" vs "admin" is a CLASSIFICATION within the same table.

  HOW WE SEPARATE THEM (no breaking change):
    - Product modules  => seeded AND linked via plan_modules / company_modules.
    - Admin modules    => seeded but NEVER added to plan_modules/company_modules.
    - Snapshot rule: modules[] = modules entitled via plan/company_modules only.
      => admin modules naturally never appear in the subscription snapshot.

  BE-TODO 1: add a discriminator on modules to make this explicit and safe:
             module_type ENUM('product','admin')  (or is_billable BOOLEAN).
             Prevents accidental gating of admin screens.
  BE-TODO 2: seed the 6 product modules (+ their permissions) so role matrices
             and entitlement both work.

  ADMIN SCREEN AUTH: keep existing permission codes (users:view, roles:edit,
  etc.) under admin modules; gate by role_permissions, independent of subscription.

Q7 — CUSTOM SUBSCRIPTION / isCustom                        [LOCKED — Option B]
================================================================================
  DECISION: Support custom bundles via company_modules (no new schema needed).

  ENTITLEMENT RESOLUTION (Phase 1):
    plan_set     = plan_modules(plan_of_active_subscription)
    company_on   = company_modules WHERE is_active = true (and not expired)
    company_off  = company_modules WHERE is_active = false
    entitled     = (plan_set  UNION  company_on)  MINUS  company_off
    isCustom     = (company_modules rows exist AND differ from plan_set)

  BACKEND CONFIRM:
    - activeCompany.subscription.isCustom is computed as above.
    - If a company has no company_modules rows -> entitled = plan_set,
      isCustom = false.
  (Optional future: dedicated custom_module_ids column — NOT needed now.)

Q11 — SUBSCRIPTION STATUS / TRIAL ENTITLEMENT              [LOCKED + FE-TODO]
================================================================================
  No active subscription -> ALLOW login, modules: [] (Option B).

  ENTITLEMENT BY SUBSCRIPTION STATUS (backend authority):
    active    -> entitled (end_date >= today OR null)
    trial     -> ENTITLED (during trial window, end_date >= today)   <-- DECISION
    pending   -> NOT entitled (maps to none)
    expired   -> NOT entitled
    cancelled -> NOT entitled

  RECONCILIATION:
    Backend treats 'trial' as live/entitled (SaaS onboarding must show modules).
    FE-TODO: getActiveSubscription() must include 'trial' (currently 'active'
             only) so client menu matches backend snapshot. Also handle
             'pending' as none (not in FE enum today).

  BACKEND CONFIRM: getActiveSubscription (server) = status IN ('active','trial')
                   AND (end_date IS NULL OR end_date >= CURRENT_DATE),
                   newest by start_date.
