================================================================================
WHAT BACKEND BUILT
================================================================================

  Separated three concepts (previously mixed in company_modules):

    Commercial entitlement   plan modules + Platform Owner GRANT/REVOKE overrides
    Tenant module settings   Company Admin enable / disable (isEnabled)
    User access              RBAC permissions[] (unchanged)

  Central service: EntitlementService (single source of truth)

  Formula:

    entitled      = planModules + GRANT − REVOKE
    enabled       = company_modules.isEnabled (default true when entitled)
    effectiveAccess = subscriptionValid AND entitled AND enabled

  Resolution priority for overrides:

    REVOKE  →  GRANT  →  PLAN default

================================================================================
403 ERROR CODES (NEW — use for user messaging)
================================================================================

  Product API denials may include:

  {
    "success": false,
    "message": "Module is not included in the company subscription.",
    "code": "MODULE_NOT_ENTITLED",
    ...
  }

  Codes:

    MODULE_NOT_ENTITLED    — company not commercially entitled to module
    SUBSCRIPTION_INACTIVE  — subscription expired / not active|trial
    MODULE_DISABLED        — Company Admin disabled the module

  Generic 403 (no code) = user lacks RBAC permission

  Suggested FE messages:

    MODULE_NOT_ENTITLED   → "This module is not included in your subscription."
    SUBSCRIPTION_INACTIVE → "Your subscription is inactive. Contact support."
    MODULE_DISABLED       → "This module has been disabled for your company."

================================================================================

    effectiveModules      from login.entitlements.modules or effective-entitlements
    permissions           from login.permissions

    hasPermission(code)           → permissions.includes(code)
