APIs — FORM CONFIGURATION (NEW)
--------------------------------------------------------------------------------

  A) GET effective built-in configuration (Settings UI)

     GET /api/v1/companies/{companyId}/form-configurations/vendor

     Permission: form_configurations:view

     Response:
     {
       "entityType": "vendor",
       "sections": [
         {
           "sectionKey": "general",
           "label": "General",
           "fields": [
             {
               "fieldKey": "vendorName",
               "label": "Vendor Name",
               "fieldType": "text",
               "visible": true,
               "required": true,
               "configurable": false,
               "source": "BUILT_IN",
               "hasOverride": false
             },
             {
               "fieldKey": "website",
               "label": "Website",
               "fieldType": "text",
               "visible": false,
               "required": false,
               "configurable": true,
               "source": "BUILT_IN",
               "hasOverride": true
             }
           ]
         }
       ]
     }

     UI rules:
       - configurable=false → toggle disabled (always visible)
       - configurable=true  → admin can toggle visible on/off


  B) Save visibility overrides

     PUT /api/v1/companies/{companyId}/form-configurations/vendor

     Permission: form_configurations:edit

     Body:
     {
       "fields": [
         { "fieldKey": "website", "isVisible": false },
         { "fieldKey": "creditLimit", "isVisible": false }
       ]
     }

     Errors:
       400 INVALID_FIELD_KEY           — unknown fieldKey
       400 PROTECTED_FIELD_CANNOT_HIDE — vendorName, supplierCode, vendorCategory
       403 Insufficient permissions


  C) Reset to ERP defaults

     DELETE /api/v1/companies/{companyId}/form-configurations/vendor

     Permission: form_configurations:edit

     Removes all company overrides → ERP defaultVisible applies.


API — FINAL VENDOR FORM SCHEMA (EXPANDED, backward compatible)
--------------------------------------------------------------------------------

  GET /api/v1/companies/{companyId}/entities/vendor/form-schema

  Permission: supply-chain module view (unchanged gate)

  LEGACY (unchanged — custom fields only):
    fields[]    — custom field definitions (same shape as before)
    sections[]  — section tab metadata [{ key, label }]

  NEW:
    builtInFields[]     — all built-in fields with effective visibility
    resolvedSections[]  — merged BUILT_IN + CUSTOM for Vendor create/edit UI

  resolvedSections example:
  {
    "sectionKey": "contact",
    "label": "Contact Details",
    "fields": [
      {
        "key": "email",
        "label": "Email",
        "fieldType": "email",
        "sectionKey": "contact",
        "source": "BUILT_IN",
        "visible": true,
        "required": false,
        "configurable": true
      },
      {
        "key": "preferred_courier",
        "label": "Preferred Courier",
        "fieldType": "text",
        "sectionKey": "custom",
        "source": "CUSTOM",
        "visible": true,
        "required": false,
        "fieldId": "...",
        "fieldName": "preferred_courier",
        ...
      }
    ]
  }

  Vendor form rendering:
    Prefer resolvedSections — only render fields where visible === true
    Hidden built-in fields: UI only (DB values preserved)


BUILT-IN FIELD KEYS (Vendor registry)
--------------------------------------------------------------------------------

  | fieldKey       | Label           | Section  | Configurable | API mapping      |
  |----------------|-----------------|----------|--------------|------------------|
  | vendorName     | Vendor Name     | general  | NO (locked)  | name             |
  | supplierCode   | Supplier Code   | general  | NO (locked)  | vendorCode       |
  | vendorCategory | Vendor Category | general  | NO (locked)  | supplierType     |
  | email          | Email           | contact  | YES          | email            |
  | phone          | Phone           | contact  | YES          | phone            |
  | website        | Website         | contact  | YES          | metadata.website |
  | paymentTerms   | Payment Terms   | payment  | YES          | metadata.*       |
  | creditLimit    | Credit Limit    | payment  | YES          | metadata.*       |

  Note: fieldKey is for configuration UI; Vendor save API still uses
  name / vendorCode / supplierType / metadata keys on create/update.
