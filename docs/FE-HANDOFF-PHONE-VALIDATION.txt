GOAL
--------------------------------------------------------------------------------

  Phone / mobile inputs must follow each country’s numbering rules.
  Example: India (+91) = exactly 10 national digits.
  Invalid: +91999455545881  (12 digits after +91) → BE returns 400.


BACKEND STATUS (READY)
--------------------------------------------------------------------------------

  Package: libphonenumber-js
  Rule:   validate → normalize → store / accept as E.164 only
          e.g. +919994555458

  Wired on BE:
    - Custom field type "phone"  (covers Vendor "Mobile 1" / mobile1 UDF)
    - Vendor.phone
    - Vendor metadata.mobile, metadata.tel2
    - Vendor bulk import phone
    - Employee mobile, company/branch phone, customer phone
    - User profile phone, company-user invite mobile, MFA SMS phone

  Default when number has NO "+" prefix: country IN (India-first).
  Numbers WITH "+" are validated for that country automatically.

2) UX PATTERN (RECOMMENDED)
================================================================================

  [ ] Country selector (flag / dial code) + national number input
  [ ] On blur / submit: parse with selected country → check isValid()
  [ ] On submit: send E.164 string only  (phone.format('E.164'))
  [ ] Show clear error before submit, e.g.
        "Enter a valid 10-digit Indian mobile number"
  [ ] Optional: format display as national (99945 55458) while editing;
      always submit E.164

  Minimal code sketch:

    import { parsePhoneNumberFromString } from 'libphonenumber-js';
    import type { CountryCode } from 'libphonenumber-js';

    function toE164(nationalOrFull: string, country: CountryCode = 'IN'): string | null {
      const raw = nationalOrFull.trim();
      if (!raw) return null;
      const parsed = parsePhoneNumberFromString(
        raw,
        raw.startsWith('+') ? undefined : country,
      );
      if (!parsed?.isValid()) return null;
      return parsed.format('E.164');
    }

  Empty / clear field → omit key or send null (same as today).

================================================================================
4) API CONTRACT
================================================================================

  Submit / expect E.164:

    "phone": "+919994555458"
    "customFields": { "mobile1": "+919994555458" }
    "metadata": { "mobile": "+919994555458", "tel2": "+442071838750" }

  Valid India examples:
    +919994555458
    9994555458          (BE treats as IN → +919994555458)

  Invalid (BE 400):
    +91999455545881     ← too many digits after +91
    12345
    "not-a-phone"

  Error shape (typical Zod / BusinessException):
    message ≈ "Invalid phone number for the selected country"
    or CF:   "\"Mobile 1\" must be a valid phone number for the country"

  FE: surface field-level error on the phone control; do not silent-drop.
