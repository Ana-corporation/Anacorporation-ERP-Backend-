2. AGREED APPROACH (DEFAULTS FROM ANALYSIS DOCS)
--------------------------------------------------------------------------------
  entityType for Vendor     : "vendor"
  v1 field types            : text, number, decimal, date, email, phone,
                              dropdown, checkbox
  storage                   : custom_field_definitions + custom_field_values
                              (optional Vendor.metadata snapshot later)
  API key in JSON           : customFields (not metadata for new UDFs)
  strict unknown keys       : YES — reject keys not in active definitions
  who manages definitions   : PLATFORM_OWNER + Company ADMIN
  field-level security (FLS): Phase 2 (not v1)
  rollout order             : Vendor → Customer → Product → others

PHASE V1-B — Admin definition APIs
----------------------------------
  Base path: /api/v1/companies/:companyId/custom-fields

  GET    ?entityType=vendor              custom_fields:view
  GET    :fieldId                        custom_fields:view
  POST   (body includes entityType=vendor) custom_fields:create
  PATCH  :fieldId                        custom_fields:edit
  DELETE :fieldId (soft deactivate)      custom_fields:delete

  Definition body (see DYNAMIC-CUSTOM-FIELDS-BACKEND-ANALYSIS.txt §8):
    fieldName, displayName, fieldType, isRequired, defaultValue,
    validation, options, sortOrder, isActive, isFilterable


PHASE V1-C — Form schema endpoint (FE dynamic form)
-----------------------------------------------------
  GET /api/v1/companies/:companyId/entities/vendor/form-schema

  Auth:
    - supply-chain:view (same as vendor list/read)
    - NO custom_fields:view required

  Returns:
    Active definitions for entityType=vendor, ordered by sortOrder
    (types, options, required, defaultValue — no admin-only internals)


PHASE V1-D — Wire Vendor CRUD
-------------------------------
  Update CreateVendorDto / UpdateVendorDto:
    - Add customFields: z.record(z.string(), z.unknown()).optional()
    - Keep metadata for backward compat short-term OR deprecate in docs

  vendors.service.ts create/update/get:
    1. Load active definitions for (companyId, 'vendor')
    2. Validate customFields (strict — unknown keys = 400)
    3. Transaction:
         a. Save vendor row
         b. Upsert custom_field_values by vendorId
    4. GET merges standard fields + customFields map

  Response shape example:
    {
      "vendorId": "1",
      "code": "V-100",
      "name": "Acme",
      ...
      "customFields": {
        "paymentTerms": "Net30",
        "preferredCurrency": "USD"
      }
    }
