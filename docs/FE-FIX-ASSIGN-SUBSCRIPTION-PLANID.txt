WHAT WENT WRONG
--------------------------------------------------------------------------------

  Current FE modal: "Assign subscription"
    - User checks individual modules (HCM, Supply Chain, Financials)
    - FE POSTs to /companies/33/subscriptions
    - Body has planId: null (or missing)

  Backend rejects with 400 Validation failed.

  This is NOT a backend bug. The API contract requires a subscription PLAN id,
  not a list of module ids.


ROOT CAUSE
--------------------------------------------------------------------------------

  BE model:

    Subscription Plan  (e.g. Professional, Demo Starter)
         ↓
      plan_modules     (which product modules the plan includes)
         ↓
    Company Subscription  (assign plan to company)

  FE model (wrong):

    User picks modules → POST subscription

  Modules are NOT sent on POST …/subscriptions.
  planId is REQUIRED.

CHANGE 2 — Send correct POST body
--------------------------------------------------------------------------------

  POST /api/v1/companies/{companyId}/subscriptions
  Perm: company_subscriptions:create
        (OWNER: platform_companies:edit aliases companies:edit / subscription:edit)

  REQUIRED fields:

  {
    "planId": "5",
    "startDate": "2026-09-02"
  }

  OPTIONAL (recommended):

  {
    "planId": "5",
    "startDate": "2026-09-02",
    "endDate": "2027-09-02",
    "billingCycle": "yearly",
    "autoRenew": true,
    "status": "active"
  }

  Field rules:

    planId        string of digits — NEVER null, NEVER omit
                  e.g. "5" not 5 is also OK (BE coerces number→string)
    startDate     YYYY-MM-DD
    endDate       YYYY-MM-DD optional (FE can auto-calc +1 year for yearly)
    billingCycle  "monthly" | "yearly" | "quarterly"
    autoRenew     boolean
    status        "active" | "trial" | "pending" | …
                  Recommend send "active" when Platform Owner assigns

CHANGE 4 — After success, refresh entitlement state
--------------------------------------------------------------------------------

    2) Refetch GET /api/v1/companies/{id}/subscription

  BE auto-creates company_modules settings (enabled=true) for plan modules.
  No follow-up POST to /modules required.

SAMPLE FE CODE (TypeScript)
================================================================================

  // types
  interface SubscriptionPlan {
    planId: string;
    planCode: string;
    name: string;
    billingCycle: 'monthly' | 'yearly' | 'quarterly';
    price: number;
    planModules?: Array<{
      module: { moduleId: string; moduleCode: string; moduleName: string };
    }>;
  }

  interface AssignSubscriptionPayload {
    planId: string;           // required — from selected plan.planId
    startDate: string;        // YYYY-MM-DD
    endDate?: string;
    billingCycle?: 'monthly' | 'yearly' | 'quarterly';
    autoRenew?: boolean;
    status?: 'active' | 'trial';
  }

  // load plans when modal opens
  async function loadPlans(): Promise<SubscriptionPlan[]> {
    const res = await api.get('/subscription/plans', {
      params: { limit: 100, isActive: true },
    });
    return res.data.data.items ?? res.data.data ?? [];
  }

  // submit — FIX: always set planId from selected plan
  async function assignSubscription(
    companyId: string,
    selectedPlan: SubscriptionPlan,
    form: { startDate: string; billingCycle: string; autoRenew: boolean },
  ) {
    if (!selectedPlan?.planId) {
      throw new Error('Select a subscription plan');
    }

    const payload: AssignSubscriptionPayload = {
      planId: String(selectedPlan.planId),
      startDate: form.startDate,
      billingCycle: form.billingCycle as AssignSubscriptionPayload['billingCycle'],
      autoRenew: form.autoRenew,
      status: 'active',
    };

    if (form.billingCycle === 'yearly') {
      payload.endDate = addYears(form.startDate, 1);
    }

    return api.post(`/companies/${companyId}/subscriptions`, payload);
  }

  { "modules": ["supply-chain"], "startDate": "2026-09-02" }

  { "planId": "", "startDate": "2026-09-02" }

  CORRECT:
  { "planId": "5", "startDate": "2026-09-02", "status": "active" }
