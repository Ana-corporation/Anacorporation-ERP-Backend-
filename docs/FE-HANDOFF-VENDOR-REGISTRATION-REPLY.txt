1. SEND VENDOR REGISTRATION (NEW API) — DONE
----------------------------------------------------------------------
  POST /api/v1/companies/:companyId/vendor-form/invitations
  Auth: Bearer   Permission: vendors:create   Company access checked

  Body:  { "toEmail": "mrkengineering2024@gmail.com", "maxSendCount": 3 }
         maxSendCount optional, 1–10, default 3. Email is stored lower-case.

  BE creates a DRAFT vendor, then sends the invitation:
    name         = toEmail (placeholder)
    email        = toEmail
    supplierType = null
    vendorCode   = DR001, DR002, ...   (placeholder — see section 3)
    isActive     = false

  Response: same shape as POST /vendors/:id/generate-email
    {
      "invitationId": "12",
      "vendorId": "123",
      "status": "SENT",
      "sendCount": 1,
      "maxSendCount": 3,
      "formInvitation": { "status": "SENT", "sendCount": 1, "maxSendCount": 3, "submittedAt": null },
      "recipientEmail": "mrkengineering2024@gmail.com",
      "generatedAt": "...", "expiresAt": "...", "lastSentAt": "...", "nextReminderAt": "...",
      "emailSent": true,
      "emailStub": false,
      "formUrl": "..."          // only when mail is not configured (emailStub: true)
    }

  Errors:
    400  invalid email / maxSendCount out of range (Zod validation)
    403  no vendors:create permission, or no access to the company
    409  code VENDOR_REGISTRATION_PENDING
         "A vendor registration is already pending for this email."
         (an unexpired PENDING/SENT invitation to that email already exists in this company)
    500  "Failed to send vendor form email" — the draft vendor is removed again,
         so nothing is left in the vendor list.

5. "LOADS FOREVER" ON swenter.com — CHECKED, BACKEND OK
----------------------------------------------------------------------
  Tested live on 27-Sep-2026:
    - GET https://swenter.com/api/v1/vendor-form/<token> answers in ~1 s
      (public route, no JWT guard; proxied by the frontend to Cloud Run).
    - Direct Cloud Run URL answers in < 1 s with
      Access-Control-Allow-Origin: https://swenter.com.
    - Unknown token -> 404 VENDOR_FORM_INVALID "Invalid vendor form link".
    - Rate limit (30 requests / minute per IP + token) returns 429 immediately.
    - Email links use https://swenter.com/vendor-form/<token> on live.
  Opening the live page with a test token showed the spinner for 1–2 s, then
  "Invalid vendor form link" — the page does finish loading. The mobile
  spinner was most likely a slow connection or an old link. The new FE
  20-second timeout message covers the slow-network case.

  Why real links showed "Invalid vendor form link":
    - Links emailed from the DEV database (Erp_test_db) point to swenter.com,
      but swenter.com only checks the live database. A backend running
      against Erp_test_db must use FRONTEND_ORIGIN=http://localhost:3001.
    - Resending cancels the previous link: older emails then show
      "This vendor form link is no longer valid" (410 VENDOR_FORM_CANCELLED).

3. POST /api/v1/vendor-form/:token/attachments   (no auth, token only)
   multipart, field "files" (repeatable) or "file".
   Response: { "files": [ ...full list for this invitation... ] }
   - Token checked first, same codes as GET (VENDOR_FORM_INVALID 404,
     VENDOR_FORM_EXPIRED / VENDOR_FORM_ALREADY_SUBMITTED / VENDOR_FORM_CANCELLED 410).
   - Real content is checked (PDF/PNG/JPEG/WEBP/DOC/XLS/DOCX/XLSX signatures;
     CSV must be text). A renamed .exe -> VENDOR_FORM_ATTACHMENT_TYPE.
   - One bad file rejects the whole request; nothing is stored.
   Errors:
     400 VENDOR_FORM_ATTACHMENT_TOO_LARGE  "<name> is larger than 10 MB"
         (if the upload library stops it first: "File is larger than 10 MB")
     400 VENDOR_FORM_ATTACHMENT_TYPE       "<name> — file type not allowed"
     400 VENDOR_FORM_ATTACHMENT_LIMIT      "You can upload up to 10 files"
     400 VENDOR_FORM_ATTACHMENT_EMPTY      (NEW) no file sent / "<name> is empty"
     403 VENDOR_FORM_ATTACHMENTS_DISABLED
     429 VENDOR_FORM_ATTACHMENT_RATE_LIMIT 20 upload+delete calls / link / 10 min
     429 VENDOR_FORM_RATE_LIMIT            existing per-IP limit (30 / min)
   IMPORTANT: Cloud Run rejects requests over 32 MB. Upload ONE file per request
   (or keep one request under 30 MB total).

4. DELETE /api/v1/vendor-form/:token/attachments/:fileAssetId
