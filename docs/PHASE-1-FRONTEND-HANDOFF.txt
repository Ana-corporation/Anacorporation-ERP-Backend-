PART 3 — BACKEND CLARIFICATIONS (ALL ANSWERED)
################################################################################

------------------------------------------------------------------------------
Q1  roleCode casing
------------------------------------------------------------------------------
  ANSWER: Backend sends "ADMIN" (uppercase). Frontend normalizes in adapter:
    roleCode: (api.roleCode || '').toLowerCase()

------------------------------------------------------------------------------
Q2  Post-login redirect
------------------------------------------------------------------------------
  ANSWER: Redirect to /dashboard. No redirectTo in company user login response.

------------------------------------------------------------------------------
Q3  CORS + cookies
------------------------------------------------------------------------------
  ANSWER:
    CORS_ORIGIN=http://localhost:3001     YES configured
    credentials: true                    YES
    Cookie sameSite: lax
    Cookie secure (dev): false
    Cookie secure (production): true

------------------------------------------------------------------------------
Q4  GET /auth/companies shape
------------------------------------------------------------------------------
  ANSWER: data is direct ARRAY (not { companies: [] })
  Each item includes employeeCode: YES

------------------------------------------------------------------------------
Q5  x-company-id header
------------------------------------------------------------------------------
  ANSWER: Optional but recommended on all authenticated calls.
  If sent, MUST match JWT cid or HTTP 403.
  JWT cid is source of truth.

------------------------------------------------------------------------------
Q6  HTTP 400 validation errors
------------------------------------------------------------------------------
  ANSWER: errors[] with { path, message, code }
  Map field: errors[i].path.join('.')

  Example:
    {
      "success": false,
      "message": "Validation failed",
      "errors": [{ "path": ["employeeCode"], "message": "...", "code": "invalid_type" }]
    }

------------------------------------------------------------------------------
Q7  Account lockout
------------------------------------------------------------------------------
  ANSWER:
    Policy lockout: HTTP 403, message "Account is locked until {ISO timestamp}"
    Wrong password / is_locked: HTTP 401
    No data.lockedUntil field — parse from message or show as-is

------------------------------------------------------------------------------
Q8  Module icon/color/sortOrder in API
------------------------------------------------------------------------------
  ANSWER: NO — not in snapshot. Frontend static map by moduleCode:

    financials     icon: finance     sortOrder: 10
    supply-chain   icon: supply      sortOrder: 11
    hcm            icon: people      sortOrder: 12
    manufacturing  icon: factory     sortOrder: 13
    crm            icon: crm         sortOrder: 14
    projects       icon: projects    sortOrder: 15

  API modules[] fields ONLY:
    moduleId, moduleCode, moduleName, isActive, permissions[]

------------------------------------------------------------------------------
Q9  permissions[] for admin sidebar
------------------------------------------------------------------------------
  ANSWER: From GET /auth/me only. Pattern: resource:action
  Demo admin gets 131 codes (DEFAULT_ADMIN_PERMISSIONS).
  Excludes platform codes (super_admins:*, platform_companies:*).

  Sample: companies:view, users:view, users:create, roles:view,
          financials:view, crm:edit, customers:read

------------------------------------------------------------------------------
Q10  POST /auth/refresh response
------------------------------------------------------------------------------
  ANSWER: FULL snapshot (same as login). permissions[] NOT included — call /auth/me.

------------------------------------------------------------------------------
Q11  Signup page Phase 1?
------------------------------------------------------------------------------
  ANSWER: B — Login only UI. Signup API exists but optional.

------------------------------------------------------------------------------
Q12  expiresIn proactive refresh?
------------------------------------------------------------------------------
  ANSWER: Refresh on 401 only. expiresIn is string "15m".

------------------------------------------------------------------------------
Q13  companyCode case sensitive?
------------------------------------------------------------------------------
  ANSWER: NO — demo_acme = DEMO_ACME = Demo_Acme

------------------------------------------------------------------------------
Q14  switch-company + permissions
------------------------------------------------------------------------------
  ANSWER: Call GET /auth/me after switch-company.

Q15  Production API URL
------------------------------------------------------------------------------

PART 4 — AUTH APIs (FULL DETAIL)
################################################################################

Base URL: http://localhost:3000/api/v1

UNWRAP HELPER (use everywhere)
------------------------------
  export function unwrap(response) {
    const envelope = response.data;
    if (!envelope?.success) throw new Error(envelope?.message || 'API failed');
    return envelope.data;
  }

------------------------------------------------------------------------------
4.1  GET /auth/company?companyCode={code}     [PUBLIC]
------------------------------------------------------------------------------
  Query: companyCode (required, case-insensitive)

  Response data:
    {
      "companyId": "15",
      "companyCode": "DEMO_ACME",
      "name": "Demo Acme Corp",
      "status": "trial"
    }

------------------------------------------------------------------------------
4.2  POST /auth/login     [PUBLIC]
------------------------------------------------------------------------------
  Request (companyId OR companyCode required):
    {
      "employeeCode": "EMP-00001",
      "password": "TestPass1!",
      "companyCode": "DEMO_ACME"
    }

  Response data:
    {
      "accessToken": "eyJ...",
      "expiresIn": "15m",
      "tokenType": "Bearer",
      "requiresCompanySelection": false,

      "companies": [
        {
          "companyId": "15",
          "companyCode": "DEMO_ACME",
          "name": "Demo Acme Corp",
          "isDefault": true,
          "status": "trial"
        }
      ],
      "activeCompany": {
        "companyId": "15",
        "companyCode": "DEMO_ACME",
        "name": "Demo Acme Corp",
        "status": "trial",
        "role": {
          "roleId": "15",
          "roleCode": "ADMIN",
          "roleName": "Administrator"
        },
        "subscription": {
          "status": "trial",
          "planCode": "DEMO_STARTER",
          "planName": "Demo Starter",
          "endDate": "2027-07-10",
          "isCustom": false
        },
        "modules": [
          {
            "moduleId": 6,
            "moduleCode": "financials",
            "moduleName": "Financials",
            "isActive": true,
            "permissions": ["view","create","edit","delete","approve"]
          }
        ]
      }
    }

  Cookie set: refresh_token (httpOnly, not in JSON)

  After login frontend MUST:
    1. sessionStorage accessToken + authContext
    2. GET /auth/me -> permissions[]
    3. hydrateFromSnapshot()
    4. redirect /dashboard

------------------------------------------------------------------------------
4.3  GET /auth/me     [BEARER]
------------------------------------------------------------------------------
  Headers:
    Authorization: Bearer <token>
    x-company-id: <companyId>   optional; must match JWT if sent

  Response data: login snapshot PLUS:
    "permissions": [ "companies:view", "users:view", ... ]  // 131 for demo admin

------------------------------------------------------------------------------
4.4  GET /auth/companies     [BEARER]
------------------------------------------------------------------------------
  Response data: ARRAY
    [
      {
        "companyId": "15",
        "companyCode": "DEMO_ACME",
        "name": "Demo Acme Corp",
        "isDefault": true,
        "status": "trial",
        "employeeCode": "EMP-00001"
      }
    ]

------------------------------------------------------------------------------
4.5  POST /auth/switch-company     [BEARER]
------------------------------------------------------------------------------
  Request: { "companyId": "16" }
  Response: same as login (new accessToken + activeCompany)
  Then: GET /auth/me for permissions[]

------------------------------------------------------------------------------
4.6  POST /auth/refresh     [COOKIE]
------------------------------------------------------------------------------
  Body: empty. Cookie refresh_token sent via withCredentials.
  Response: FULL login snapshot (not token-only).
  permissions[]: call /auth/me separately.

------------------------------------------------------------------------------
4.7  POST /auth/logout     [BEARER + COOKIE]
------------------------------------------------------------------------------
  Response data: { "message": "Logged out successfully" }
  Cookie cleared. Clear sessionStorage.

------------------------------------------------------------------------------
4.8  POST /auth/signup     [PUBLIC — optional UI]
------------------------------------------------------------------------------
  Request:
    {
      "email": "owner@mycompany.com",
      "password": "SecurePass1",
      "confirmPassword": "SecurePass1",
      "firstName": "Owner",
      "lastName": "Name",
      "companyName": "My Company Ltd"
    }
  Password: 8+ chars, upper, lower, digit.
  Response: same as login.

PART 6 — SESSION STORAGE + AXIOS + GUARDS
################################################################################

SESSION STORAGE
---------------
  accessToken     JWT string
  authContext     { user, activeCompanyId, companies, activeCompany }
  NEVER store refreshToken or password

AXIOS REQUEST INTERCEPTOR
-------------------------
  Add Authorization: Bearer <accessToken from sessionStorage>
  Optional: x-company-id: activeCompanyId

AXIOS 401 INTERCEPTOR
---------------------
  POST /auth/refresh -> save new accessToken -> retry request
  On fail: clear storage -> /auth/login

AUTH GUARD
----------
  No token -> /auth/login
  Token but no state -> GET /auth/me -> hydrate

PUBLIC ROUTES
-------------
  /, /auth/login

PART 9 — QUICK REFERENCE + auth-api.js STUBS
################################################################################

  GET    /auth/company           Public
  POST   /auth/login             Public
  POST   /auth/signup            Public
  POST   /auth/refresh           Cookie
  GET    /auth/me                Bearer
  GET    /auth/companies         Bearer -> array
  POST   /auth/switch-company    Bearer
  POST   /auth/logout            Bearer + cookie

  // auth-api.js
  import api from './axios';
  import { unwrap } from './unwrap';

  export const resolveCompany = (code) =>
    unwrap(api.get('/auth/company', { params: { companyCode: code } }));

  export const login = (body) => unwrap(api.post('/auth/login', body));

  export const getMe = () => unwrap(api.get('/auth/me'));

  export const getCompanies = () => unwrap(api.get('/auth/companies'));

  export const switchCompany = (companyId) =>
    unwrap(api.post('/auth/switch-company', { companyId }));

  export const refresh = () => unwrap(api.post('/auth/refresh'));

  export const logout = () => unwrap(api.post('/auth/logout'));
