0. ONE-LINE VERDICT
--------------------------------------------------------------------------------

  The Word file is NOT a text spec — it is 9 SAP Business One "Item Master
  Data" UI screenshots (table OITM). It defines a full ERP item master with
  header + 9 tabs + a custom right-hand "General" panel.

  Recommendation for OUR ERP:
    Build a company-scoped Item Master using the SAME patterns as Vendor
    (shared Neon + companyId, structured columns + optional metadata JSON,
    reusable for custom fields later). Do NOT clone SAP 1:1 in v1.

3.9 PROPERTIES TAB
------------------------------------------------------------------------------

  64 boolean property slots (SAP B1 classic).
  UI: "Items Property 1" … "Items Property 64" + Select All / Clear.

  OUR ERP recommendation:
    Do NOT create 64 boolean columns.
    Use either:
      - custom field definitions (entityType=item) with checkbox type, OR
      - item_properties JSON / bit flags table keyed by property code.

4. RECOMMENDED DATA MODEL (OUR ERP — NOT SAP CLONE)
--------------------------------------------------------------------------------

  Align with locked platform patterns:
    ✓ Shared Neon DB + companyId
    ✓ Soft delete + audit (createdBy/At, updatedBy/At)
    ✓ Lookups as master tables (or enums for small sets)
    ✓ Child tables for warehouse stock / attachments
    ✓ Optional customFields later (entityType = item)

------------------------------------------------------------------------------
4.1 TABLES — VERSION 1 (MUST HAVE)
------------------------------------------------------------------------------

  A) items                         — master header + general + key flags
  B) item_purchase_data            — 1:1 purchasing (or columns on items)
  C) item_sales_data               — 1:1 sales
  D) item_inventory_settings       — 1:1 valuation / default levels
  E) item_warehouse_stock          — 1:N per warehouse (qty + bins)
  F) item_planning_data            — 1:1 planning
  G) item_production_data          — 1:1 production flags (BOM later)
  H) item_attachments              — 1:N files (optional v1.1)

  Lookup masters (company or shared):
    item_groups
    uom_groups / units_of_measure
    manufacturers (optional)
    brands / divisions / major_groups (or metadata + custom fields)

  Practical v1 simplification (recommended):
    ONE table `items` with JSON columns for purchase/sales/planning/
    production extras that are rarely filtered,
    PLUS `item_warehouse_stock` for real inventory numbers.

4.2 SUGGESTED `items` CORE COLUMNS (v1)
------------------------------------------------------------------------------

  item_id                 BIGSERIAL PK

  is_inventory_item       BOOLEAN DEFAULT true

  is_purchase_item        BOOLEAN DEFAULT true

  manufacturer_id         BIGINT NULL
  shipping_type           VARCHAR(40) NULL

  status                  VARCHAR(20) DEFAULT 'active' -- active|inactive|advanced
  active_from             DATE NULL
  active_to               DATE NULL

  net_weight_kg           DECIMAL(18,6) NULL
  gross_weight_kg         DECIMAL(18,6) NULL

  core_activity           VARCHAR(80) NULL
  major_group             VARCHAR(120) NULL
  brand_name              VARCHAR(80) NULL
  effective_date          DATE NULL
  customer_stock_no       VARCHAR(80) NULL
  stock_dio_days          INT NULL

  remarks                 TEXT NULL
  purchase_json           JSONB NULL             -- purchasing tab bag
  sales_json              JSONB NULL
  inventory_json          JSONB NULL             -- valuation defaults

  @@unique([company_id, item_code])

  @@index([company_id, item_group_id])

6. GAP vs CURRENT BACKEND
--------------------------------------------------------------------------------

  Current stub (src/modules/inventory/items):
    CreateProductDto ≈ sku, name, categoryId, uom, cost/price,
                       isManufactured / isPurchasable / isSaleable, metadata

  That is a thin Product — NOT SAP Item Master.

  Gap:
    Missing almost all tabs (purchase/sales/inventory grid/planning/
    production/properties/attachments) and AnaCorp classification panel.

  Decision:
    Rename mental model from "Product" → "Item" (Item Master).
    Either evolve Product into Item, or introduce Item and deprecate Product.
    Prefer ONE entity: Item (itemCode), keep Product alias only if FE needs it.
