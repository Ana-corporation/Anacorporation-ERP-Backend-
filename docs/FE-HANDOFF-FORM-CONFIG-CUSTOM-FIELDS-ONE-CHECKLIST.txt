0) ARCHITECTURE (DO NOT MIX THESE)
--------------------------------------------------------------------------------

  Layer 1 — Built-in Field Registry (BE code + deploy)
    Standard ERP fields: Name, Code, Phone, Email, Bank fields, etc.
    New built-ins = backend code change + deploy. FE does not create them.

  Layer 2 — Form Configuration (Settings)
    Per-company visibility for BUILT-IN fields ONLY.
    Stored in company_field_configurations.
    Protected fields (Name, Code, etc.) cannot be hidden.
    Custom fields NEVER appear on this page.

  Layer 3 — Custom Fields (Settings)
    Company UDFs only.
    Stored in custom_field_definitions.
    Creating/editing a custom field must NOT call Form Configuration APIs
    and must NOT expect the field to show on the Form Configuration list.

  Layer 4 — Runtime Form Schema (Vendor / Item create · edit · view)
    GET /api/v1/companies/{companyId}/entities/{entityType}/form-schema
    Merges:
      - Built-in registry
      - Company built-in visibility overrides
      - Active custom fields
    Preferred response for rendering:
      - resolvedSections   ← PRIMARY for form UI
      - builtInFields      ← secondary (visibility / debug)
    Legacy fields[] = custom definitions only — NOT the main render source.

3) FORM CONFIGURATION PAGE (BUILT-INS ONLY)
================================================================================

  Entity tabs: Vendor | Item

  APIs
  ----
  GET    /api/v1/companies/{companyId}/form-configurations/vendor
  GET    /api/v1/companies/{companyId}/form-configurations/item
  PUT    /api/v1/companies/{companyId}/form-configurations/vendor|item
  DELETE /api/v1/companies/{companyId}/form-configurations/vendor|item

  GET response (shape)
  --------------------
  {
    "entityType": "vendor",
    "sections": [
      {
        "sectionKey": "general",
        "label": "General",
        "fields": [
          {
            "fieldKey": "vendorName",
            "label": "Vendor Name",
            "fieldType": "text",
            "visible": true,
            "required": true,
            "configurable": false,   // ← lock toggle in UI
            "source": "BUILT_IN",
            "hasOverride": false
          }
        ]
      }
    ]
  }

  PUT body
  --------
  {
    "fields": [
      { "fieldKey": "website", "isVisible": false },
      { "fieldKey": "contactEmail", "isVisible": true }
    ]
  }

  UI rules
  --------
  [ ] Render sections/fields from Form Configuration GET only
  [ ] Every row is source BUILT_IN — never inject Custom Field definitions here
  [ ] If configurable === false → toggle disabled (Name / Code / protected)
  [ ] Show hasOverride indicator if useful
  [ ] On PUT success → refetch Form Configuration GET
  [ ] On PUT success → invalidate / refetch any open Vendor/Item form-schema cache
  [ ] On DELETE (reset) → same refetch / invalidate
  [ ] Handle errors: PROTECTED_FIELD_CANNOT_HIDE, INVALID_FIELD_KEY

5) VENDOR / ITEM CREATE · EDIT · VIEW (RUNTIME FORM)
================================================================================

  API (required)
  --------------
  GET /api/v1/companies/{companyId}/entities/vendor/form-schema
  GET /api/v1/companies/{companyId}/entities/item/form-schema

  Preferred response usage
  ------------------------
  resolvedSections[]     ← PRIMARY render tree
    sectionKey, label, fields[]
      each field:
        source: "BUILT_IN" | "CUSTOM"
        key / fieldKey / fieldName
        apiKey          (built-in bind path, e.g. name, metadata.website, purchase.weight)
        label, fieldType, required, visible

  builtInFields[]        ← all built-ins with effective visibility (optional)

  fields[]               ← LEGACY custom-only list — do NOT use as sole form source
  sections[]             ← tab metadata only — do NOT treat as full field tree

  Render rules
  ------------
  [ ] On mount: always fetch form-schema for the entityType
  [ ] Build UI from resolvedSections (skip fields with visible === false if present)
  [ ] BUILT_IN → bind to main Vendor/Item DTO via apiKey / key
  [ ] CUSTOM   → bind to customFields payload keyed by fieldName
  [ ] Hidden built-in: omit from UI; do not send nulls that wipe stored values on PATCH
  [ ] After Form Configuration or Custom Fields change: refetch form-schema before open / on focus

  Submit mapping
  --------------
  Built-in visible fields  → core / metadata / bags on vendor|item body
  Custom visible fields    → customFields: { [fieldName]: value }


================================================================================
6) REFETCH / CACHE RULES (CRITICAL)
================================================================================

  After Form Configuration PUT or DELETE:
    1. Refetch form-configurations GET for that entity
    2. Invalidate cached form-schema for vendor and/or item
    3. If create/edit form is open → refetch form-schema immediately

  After Custom Fields create / edit / deactivate:
    1. Refetch custom-fields list
    2. Invalidate / refetch form-schema for that entityType

  Do not wait for hard refresh / re-login for schema changes
  (permissions still require re-login only when roles change).
