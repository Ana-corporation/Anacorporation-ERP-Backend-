2) STORE CATEGORY   /companies/{companyId}/store-categories
================================================================================

  Perms:   warehouses:view | create | edit | delete
  Routes:  GET list · GET /:id · POST · PATCH /:id · DELETE /:id

  Body:
    { "name": "Raw Material Store", "codePrefix": "RMS",
      "description": null, "sortOrder": 1, "isActive": true }

  - codePrefix: 2-6 letters/digits, starts with a letter. "rms " → "RMS".
  - name and codePrefix are unique per company (deleted ones can be reused).
  - codePrefix can't change once locations use it.
  - Delete blocked while locations use it. Deactivate instead.
  - Inactive category can't be picked for a NEW location; locations that have it keep it.
  - GET list returns active AND inactive. Location dropdown: show isActive=true only.

  Row:
    { "storeCategoryId": "5", "companyId": "28", "name": "Raw Material Store",
      "codePrefix": "RMS", "description": null, "sortOrder": 1, "isActive": true,
      "locationCount": 2, "createdAt": "...", "updatedAt": "..." }

  GET list is not paginated but uses the list shape:
    { "items": [...], "total": 7, "page": 1, "limit": 7 }

  Seeded:
    Ana (28): RMS, SPR, FGS, BOS, ELS, GEN, OIL (Raw Material, Spares, Finished Goods,
              Bought Out, Electrical, General, Oil Store)
    Every other company + every new company: General Store / GEN

3) INVENTORY LOCATION   /companies/{companyId}/warehouses
================================================================================

  Perms:   warehouses:view | create | edit | delete

  POST /companies/28/warehouses
    { "name": "Raw Material Store - Main", "branchId": "2", "storeCategoryId": "5",
      "binManagement": true, "isDefault": true }
  → 201
    { "warehouseId": "6", "uuid": "3f2c…", "warehouseCode": "RMS-001", "locationCode": "RMS-001",
      "name": "Raw Material Store - Main", "branchId": "2", "address": "<site address>",
      "storeCategoryId": "5",
      "storeCategory": { "storeCategoryId": "5", "name": "Raw Material Store", "codePrefix": "RMS" },
      "locationType": "Store", "binManagement": true, "isDefault": true, "isActive": true,
      "binCount": 0, ... }

  CODE
    - Always generated by BE. Don't send it (ignored). Never changes. Show read-only.
    - warehouseCode and locationCode are the same value.
    - Prefix = category codePrefix → RMS-001, RMS-002 … per category, per company.
      Another company starts at RMS-001 too.
    - No storeCategoryId → prefix from locationType (old way, still works):
        RawMaterialStore RMS · SparesStore SPR · FinishedGoodsStore FGS · BoughtOutStore BOS
        ElectricalStore ELS · GeneralStore GEN · OilStore OIL
        Store (default) GEN · Warehouse WHS · Godown GDN · Other OTH
    - Deleted codes are never reused. Old codes (e.g. MAIN_STORE) stay as they are.

  BIN COUNT
    List and GET /:id return "binCount" = active, not-deleted bins of the location.
    Use it instead of loading all bins to count them.

  RULES
    - branchId (site) required on create; can't be null on edit.
      Missing / null → 400 "Validation failed" (no code). Site of another company → 404.
    - address empty on create → copied from the site.
    - isDefault: one default PER SITE. New default clears the old one in that site only.
    - PATCH { "storeCategoryId": null } clears the category (code unchanged), only while unused.
    - After the location has bins, stock or inventory documents:
        site can't change        → LOCATION_SITE_LOCKED
        category can't change    → LOCATION_CATEGORY_LOCKED
        delete with bins         → LOCATION_HAS_BINS
        delete with stock/docs   → LOCATION_IN_USE  (deactivate instead: isActive=false)
      Name, address, isActive, isDefault can always change.
    - binManagement off while bins exist            → LOCATION_HAS_BINS
    - binManagement on while stock is not in a bin  → LOCATION_HAS_UNBINNED_STOCK

  LIST FILTERS
    ?siteId=2  (branchId= also works)   ?storeCategoryId=5   ?isActive=true
    plus the normal page, limit, search, sortBy, sortOrder.

4) STORAGE BIN   /companies/{companyId}/storage-bins
================================================================================

  Perms:   warehouses:view | create | edit | delete

  POST /companies/28/storage-bins
    { "warehouseId": "6", "binCode": "R01-S04-P03", "binName": "Rack 1 Shelf 4", "isActive": true }

  - binCode typed by user; BE trims + uppercases.
  - Unique per location. Same code in another location is fine.
  - A deleted bin's code can't be reused in the same location.
  - Location must be active and have binManagement=true.
  - Location of another company → 404.
  - Bins can't move: PATCH ignores warehouseId. Show Location read-only on edit.
  - Delete blocked when the bin has stock / documents → deactivate instead.
  - Response has warehouseId AND inventoryLocationId (same).
  - List: GET /companies/28/storage-bins?warehouseId=6

  BULK CREATE (Generate Bins)
    POST /companies/28/storage-bins/bulk          perm warehouses:create
      { "warehouseId": "6",
        "bins": [ { "binCode": "R01-S01", "binName": "Rack 1 Shelf 1" },
                  { "binCode": "R01-S02", "binName": "Rack 1 Shelf 2" } ],
        "skipExisting": true }
    → 201
      { "created": [ <bin rows, same shape as single POST, in request order> ],
        "skipped": [ { "binCode": "R01-S01", "reason": "EXISTS" | "DELETED_CODE" } ] }

    - Same location rules as single POST (404 / LOCATION_INACTIVE / BIN_MANAGEMENT_DISABLED).
    - Max 500 bins → 400 BIN_BULK_LIMIT.
    - Same code twice in the request → 400 BIN_CODE_DUPLICATE, errors[].field = "bins.<i>.binCode".
    - skipExisting true  → clashes skipped + listed in "skipped"; the rest created.
      skipExisting false (default) → any clash = 409 BIN_CODE_DUPLICATE, nothing created.
    - One transaction.

5) DOCUMENTS — Opening Stock · Material Issue · Stock Adjustment
================================================================================

  Flow:  DRAFT --(Post)--> POSTED
    - DRAFT: create / edit / delete freely. Stock is NOT changed.
    - Post: stock + ledger updated in one step. All lines or nothing.
    - POSTED: read-only. Fix mistakes with a Stock Adjustment.

  Routes (<doc> = opening-stock | material-issues | stock-adjustments):
    GET    /<doc>               List
    GET    /<doc>/:id           View
    POST   /<doc>               Create draft
    PUT    /<doc>/:id           Save draft (send header + ALL lines; lines are replaced)
    DELETE /<doc>/:id           Delete draft
    POST   /<doc>/:id/post      Post (no body)

  List filters: page, limit (max 200), search (document number), status=DRAFT|POSTED,
    fromDate, toDate, itemId, documentNumber, sortBy, sortOrder=asc|desc.
  List: { "items": [ { ...header without lines..., "lineCount": 3 } ], "total", "page", "limit" }

  Buttons:  DRAFT → Edit, Delete, Post      POSTED → View only

  PERMISSIONS
    opening_stock:view | create | edit | delete | approve
    material_issues:view | create | edit | delete | approve
    stock_adjustments:view | create | edit | delete | approve
    inventory_stock:view            Current Stock + Stock Ledger
    "approve" = the Post button. Company ADMIN roles get all automatically.
    Users must log out / in to receive new codes. Old supply-chain:<action> also passes.

  DROPDOWNS
    Item      GET /companies/:companyId/items          (inventory items only)
    Site      GET /companies/:companyId/branches
    Location  GET /companies/:companyId/warehouses?siteId=<site>
    Bin       GET /companies/:companyId/storage-bins?warehouseId=<location>
    Dept.     GET /companies/:companyId/departments    (Material Issue only)
    Bin field: required when the location has binManagement=true; hidden when false.
    UoM: read-only, from the Item Master. BE fills it.

  BODIES
    Opening Stock
      { "documentDate": "2026-10-01", "remarks": "Go-live balances",
        "lines": [ { "itemId": "101", "siteId": "2", "inventoryLocationId": "3",
                     "storageBinId": "7", "quantity": "100", "unitPrice": "12.50", "remarks": "" } ] }

    Material Issue  (requestedBy required)
      { "documentDate": "2026-10-03", "requestedBy": "Line 2 Supervisor",
        "issuedBy": "Store Keeper", "departmentId": "5", "purpose": "Breakdown maintenance",
        "remarks": "",
        "lines": [ { "itemId": "101", "siteId": "2", "inventoryLocationId": "3",
                     "storageBinId": "7", "quantity": "30", "remarks": "" } ] }

    Stock Adjustment  (reason required; send the COUNTED quantity)
      { "documentDate": "2026-10-05", "reason": "Cycle count", "remarks": "",
        "lines": [ { "itemId": "101", "siteId": "2", "inventoryLocationId": "3",
                     "storageBinId": "7", "physicalQuantity": "95" } ] }
      BE works out system qty and difference: system 97, physical 100 → IN 3;
      system 97, physical 95 → OUT 2.

  LINE RULES
    - itemId and inventoryLocationId required.
    - siteId optional (taken from the location); if sent, must be the location's site.
    - storageBinId: required when the location uses bins, not allowed when it doesn't.
    - Location and bin must be active.
    - uom optional; if sent, must equal the Item Master UoM.
    - 1 to 500 lines.
    - Opening / Issue quantity > 0. Adjustment physicalQuantity >= 0. unitPrice >= 0 (optional).
    - Item must be an active inventory item. Batch / serial items rejected for now.
    - Adjustment: same item + location + bin only once.

  RESPONSE (create / save / view / post)
    { "documentId": "45", "documentType": "MATERIAL_ISSUE",
      "documentNumber": "MI-000001",          // OS- / MI- / SA- + 6 digits, auto
      "documentDate": "2026-10-03", "status": "DRAFT", "remarks": "",
      "requestedBy": "...", "issuedBy": "...", "departmentId": "5",      // Material Issue only
      "department": { "departmentId": "5", "departmentCode": "MNT", "name": "Maintenance" },
      "purpose": "...",
      "postedAt": null, "postedBy": null, "postedByName": null,
      "createdBy": "12", "createdByName": "Ravi Kumar", "createdAt": "...",
      "updatedBy": null, "updatedByName": null, "updatedAt": "...",
      "lines": [
        { "lineId": "301", "lineNo": 1,
          "itemId": "101", "partNumber": "P-100", "partName": "Bearing 6205", "uom": "NOS",
          "siteId": "2", "siteCode": "S1", "siteName": "Chennai Plant",
          "inventoryLocationId": "3", "locationCode": "RMS-001", "locationName": "Main Store",
          "storageBinId": "7", "binCode": "A-01", "binName": null,
          "remarks": "", "quantity": "30", "availableQuantity": "100" } ] }

    Extra line fields by type:
      Opening Stock     quantity, unitPrice
      Material Issue    quantity, availableQuantity (live while DRAFT; null after posting)
      Stock Adjustment  systemQuantity, physicalQuantity, difference, adjustmentType IN|OUT|null
                        DRAFT: live stock. POSTED: values used at posting, frozen.
    Stock Adjustment header has "reason" instead of the issue fields.

7) STOCK LEDGER   GET /inventory/stock/ledger      perm inventory_stock:view
================================================================================

  Filters: itemId, siteId, inventoryLocationId, storageBinId, fromDate, toDate,
    movementType (comma list: OPENING_STOCK,MATERIAL_ISSUE,ADJUSTMENT_IN,ADJUSTMENT_OUT),
    documentNumber, page, limit.   Rows are oldest first.

    { "items": [
        { "entryId": "900", "transactionDate": "2026-10-03", "transactionType": "MATERIAL_ISSUE",
          "referenceDocumentId": "45", "referenceDocumentNumber": "MI-000001",
          "itemId": "101", "partNumber": "P-100", "partName": "Bearing 6205",
          "siteId": "2", "siteCode": "S1", "siteName": "Chennai Plant",
          "inventoryLocationId": "3", "locationCode": "RMS-001", "locationName": "Main Store",
          "storageBinId": "7", "binCode": "A-01", "binName": null,
          "quantityIn": "0", "quantityOut": "30", "runningBalance": "70", "uom": "NOS",
          "unitCost": null, "totalValue": null,
          "createdBy": "12", "createdByName": "Ravi Kumar", "createdAt": "..." } ],
      "total": 6, "page": 1, "limit": 20, "openingBalance": "100" }

  - runningBalance is per item and includes everything before fromDate. Don't sum on the FE.
  - openingBalance only when itemId AND fromDate are given; otherwise null.
  - Filtering by type / document number hides rows but keeps the true running balance.
  - unitCost / totalValue only for Opening Stock.
  - Click referenceDocumentNumber → open by transactionType:
      OPENING_STOCK → opening-stock · MATERIAL_ISSUE → material-issues
      ADJUSTMENT_IN / ADJUSTMENT_OUT → stock-adjustments

  NOTES
  - Current Stock / Ledger only show locations the user may see (data access policy).
  - Two users posting at once cannot oversell; one gets INSUFFICIENT_STOCK.
  - Deleted draft numbers are not reused. Backdated posting allowed (ledger orders by date).
  - Item Master warehouse rows: qtyOnHand is READ-ONLY now (filled by postings; FE values
    ignored). Removing a row that still has stock → 409 ITEM_WAREHOUSE_HAS_STOCK.

8) ERRORS
================================================================================

  Body:  { "success": false, "message": "...", "code": "...",
           "errors": [ { "field": "lines[0].quantity", "message": "..." } ] }
  FE reads "code" to decide, "message" to show, errors[].field to mark the field / line.

  Body validation (missing / wrong field): 400 "Validation failed", no code,
           "errors": [ { "path": ["branchId"], "message": "..." } ]
  Not found (other company's id): 404 "<Thing> not found", no code.

  Store categories
    404 STORE_CATEGORY_NOT_FOUND       (also on warehouses POST/PATCH, field storeCategoryId)
    409 STORE_CATEGORY_NAME_EXISTS
    409 STORE_CATEGORY_PREFIX_EXISTS
    400 STORE_CATEGORY_PREFIX_LOCKED
    409 STORE_CATEGORY_IN_USE
    400 STORE_CATEGORY_INACTIVE

  Locations
    400 LOCATION_SITE_LOCKED           → disable Site
    400 LOCATION_CATEGORY_LOCKED       → disable Category
    400 LOCATION_HAS_BINS              → delete bins first / offer Deactivate
    400 LOCATION_HAS_UNBINNED_STOCK    → show message
    409 LOCATION_IN_USE                → offer Deactivate

  Bins
    400 / 409 BIN_CODE_DUPLICATE       (400 = twice in one bulk request)
    409 BIN_IN_USE                     → offer Deactivate
    400 BIN_BULK_LIMIT
    400 BIN_MANAGEMENT_DISABLED
    400 LOCATION_INACTIVE

  Stock documents
    400 INSUFFICIENT_STOCK                         Not enough stock to post; stays DRAFT.
    409 INVENTORY_DOCUMENT_ALREADY_POSTED          Post on a posted doc (double click). Reload.
    409 INVENTORY_DOCUMENT_POSTED                  Edit / delete of a posted doc.
    400 INVENTORY_ITEM_NOT_FOUND                   Item not in this company.
    400 INVENTORY_ITEM_NOT_STOCKABLE               Inactive or not an inventory item.
    400 INVENTORY_ITEM_BATCH_SERIAL_NOT_SUPPORTED  Batch / serial item.
    400 INVENTORY_UOM_MISMATCH                     uom differs from the Item Master.
    400 INVENTORY_LOCATION_NOT_FOUND               Location not in this company.
    400 INVENTORY_LOCATION_INACTIVE                Location is inactive.
    400 INVENTORY_SITE_NOT_FOUND                   Site not in this company / inactive.
    400 INVENTORY_SITE_LOCATION_MISMATCH           Location not in the selected site.
    400 INVENTORY_BIN_REQUIRED                     Location uses bins; pick a bin.
    400 INVENTORY_BIN_NOT_ALLOWED                  Location has no bins; clear the bin.
    400 INVENTORY_BIN_NOT_FOUND                    Bin not in that location.
    400 INVENTORY_BIN_INACTIVE                     Bin is inactive.
    400 INVENTORY_DUPLICATE_LINE                   Adjustment: same item + location + bin twice.
    400 INVENTORY_DEPARTMENT_NOT_FOUND             Material Issue department not found.
    400 INVENTORY_INVALID_DATE                     Bad documentDate.
    403 INVENTORY_LOCATION_OUT_OF_SCOPE            Outside the user's data access policy.
    404                                            Document not found in this company.
    409 ITEM_WAREHOUSE_HAS_STOCK                   Item Master: warehouse row still has stock.
