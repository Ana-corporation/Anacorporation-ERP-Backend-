SECTION 3 — SIGNUP API
================================================================================

  POST /api/v1/auth/signup
  Auth: None (public)

REQUEST BODY (all fields required)
--------------------------------
  {
    "email": "owner2@mycompany.com",
    "password": "SecurePass1",
    "confirmPassword": "SecurePass1",
    "firstName": "Owner",
    "lastName": "Name",
    "companyName": "My Company Ltd"
  }

SUCCESS RESPONSE
----------------
  HTTP 200 (not 201)
  {
    "success": true,
    "message": "Success",
    "data": {
      "accessToken": "eyJ...",
      "expiresIn": "15m",
      "tokenType": "Bearer",
      "requiresCompanySelection": false,
      "user": { "userId", "username", "displayName", "email" },
      "companies": [ ... ],
      "activeCompany": { ... modules, role, subscription ... }
    }
  }

  refresh_token cookie set automatically (httpOnly — do not read in JS).

AFTER SIGNUP
------------
  1. Store accessToken in sessionStorage
  2. Call GET /auth/me for permissions[]
  3. Employee code assigned automatically (e.g. EMP-00001 style)
  4. Or login later with employeeCode + companyCode from signup response

FRONTEND UNWRAP
---------------
  const payload = response.data.data;   // not response.data directly

SECTION 4 — SIGNUP ERRORS (WHAT THEY MEAN + FIX)
================================================================================

------------------------------------------------------------------------------
ERROR A — HTTP 409 Conflict
------------------------------------------------------------------------------
  MEANING: Email already registered in database.

  Response:
    {
      "success": false,
      "message": "Email is already registered",
      "data": null,
      "path": "/api/v1/auth/signup"
    }

  FIX:
    - Use a different email address
    - Do NOT use admin@demo-acme.com (demo seed user)

  UI MESSAGE: "This email is already registered. Try another email or log in."

------------------------------------------------------------------------------
ERROR B — HTTP 400 Validation
------------------------------------------------------------------------------
  MEANING: Invalid request body (password rules, missing fields, etc.)

  PASSWORD RULES (backend enforced):
    - Minimum 8 characters
    - At least 1 UPPERCASE letter
    - At least 1 lowercase letter
    - At least 1 digit (0-9)

  VALID passwords:   SecurePass1, TestPass1!, MyPass99
  INVALID passwords: weak, password, 12345678, alllowercase1

  PASSWORD MISMATCH:
    If password !== confirmPassword:
      message: "Password and confirm password do not match"

  VALIDATION ERROR SHAPE (Zod):
    {
      "success": false,
      "message": "Validation failed",
      "data": null,
      "errors": [
        {
          "path": ["password"],
          "message": "Password must be at least 8 characters and include uppercase, lowercase, and a number",
          "code": "invalid_format"
        }
      ],
      "path": "/api/v1/auth/signup"
    }

  FRONTEND MAP FIELD ERRORS:
    const field = error.path?.join('.') || 'form';
    const msg = error.message;

  UI MESSAGE: Show message under password field or toast.

------------------------------------------------------------------------------
ERROR C — Network error / Failed to fetch / CORS
------------------------------------------------------------------------------
  MEANING: Request never reached backend OR browser blocked response.

  CHECKLIST:
    [ ] Backend running?  npm run start:dev
    [ ] URL correct?      http://localhost:3000/api/v1/auth/signup
    [ ] CORS_ORIGIN=http://localhost:3001 in backend .env
    [ ] Frontend on port 3001?
    [ ] withCredentials: true on axios
    [ ] Restart backend after .env change

  UI MESSAGE: "Cannot reach server. Check backend is running on port 3000."

------------------------------------------------------------------------------
ERROR D — HTTP 401 / 403 on other calls (not signup)
------------------------------------------------------------------------------
  401 = bad token or wrong login credentials
  403 = company suspended, account locked, x-company-id mismatch

  Signup itself is public — should not get 401 on POST /signup.

SECTION 6 — SIGNUP vs LOGIN (PHASE 1)
================================================================================

  | Feature          | Signup                    | Login                    |
  |------------------|---------------------------|--------------------------|
  | Endpoint         | POST /auth/signup         | POST /auth/login         |
  | Identifier       | email                     | employeeCode             |
  | Company          | companyName (creates new) | companyCode or companyId |
  | Phase 1 UI       | Optional                  | Required                 |

  Backend decision: Login-only UI is OK for Phase 1.
  Signup API works if frontend builds registration page.
