1) SETTINGS → CUSTOM FIELDS (MAIN CHANGE)
================================================================================

  Today: module hardcoded to "vendor".
  Change: Module dropdown driven by meta.

  On page load
  ------------
  GET /api/v1/custom-fields/meta/modules
  Permission: custom_fields:view

  Response (data shape):
  {
    "items": [
      { "entityType": "vendor", "label": "Vendor", "productModule": "supply-chain" },
      { "entityType": "item",   "label": "Item",   "productModule": "supply-chain" }
    ]
  }

  UI:
  [ ] Module select: options from items[].entityType / label
  [ ] Default selection: vendor (backward compatible) OR last-used
  [ ] On module change → reload sections meta + field list for that entityType


  Sections + reserved names (create/edit form)
  --------------------------------------------
  GET /api/v1/custom-fields/meta/modules/{entityType}/sections
  Permission: custom_fields:view

  Example — Item:
  GET /api/v1/custom-fields/meta/modules/item/sections

  Response:
  {
    "entityType": "item",
    "sections": [
      { "key": "header",         "label": "Header" },
      { "key": "general",        "label": "General" },
      { "key": "classification", "label": "Classification" },
      { "key": "purchasing",     "label": "Purchasing" },
      { "key": "sales",          "label": "Sales" },
      { "key": "inventory",      "label": "Inventory" },
      { "key": "planning",       "label": "Planning" },
      { "key": "production",     "label": "Production" },
      { "key": "properties",     "label": "Properties" },
      { "key": "remarks",        "label": "Remarks" },
      { "key": "custom",         "label": "Custom" }
    ],
    "reservedFieldNames": [ "itemCode", "description", ... ],
    "reservedDisplayNames": [ "Item Code", "Description", ... ]
  }

  NOTE: BE returns section objects as { key, label }.
        Map to sectionKey in create body (see below).
        Prefer existing tabs; sectionKey=custom is fallback only.

  UI:
  [ ] Section dropdown = sections from THIS entityType (not Vendor catalog)
  [ ] Client-side warn if displayName matches reservedDisplayNames
  [ ] Client-side warn if fieldName matches reservedFieldNames
  [ ] Still rely on BE 400 for final enforcement


  List definitions
  ----------------
  GET /api/v1/companies/{companyId}/custom-fields?entityType=item
  GET /api/v1/companies/{companyId}/custom-fields?entityType=item&groupedBySection=true
  Optional: &includeInactive=true

  Permission: custom_fields:view

  [ ] Always pass entityType from Module select
  [ ] Do not mix Vendor + Item rows in one list


  Create
  ------
  POST /api/v1/companies/{companyId}/custom-fields
  Permission: custom_fields:create

  Body example:
  {
    "entityType": "item",
    "sectionKey": "general",
    "displayName": "Preferred Finish",
    "fieldType": "text",
    "isRequired": false,
    "sortOrder": 40,
    "isFilterable": false,
    "helpText": "optional",
    "validation": null,
    "options": null
  }

  Notes:
  - fieldName optional — BE auto-slugs from displayName
  - sectionKey REQUIRED — must be in Item sections catalog → else 400
  - reserved Item displayName / fieldName → 400
  - Supported fieldType (v1): text, textarea, number, decimal, date,
    email, phone, dropdown, checkbox


  Update / soft-delete
  --------------------
  PATCH  /api/v1/companies/{companyId}/custom-fields/{fieldId}
  DELETE /api/v1/companies/{companyId}/custom-fields/{fieldId}

  Permission: custom_fields:edit | custom_fields:delete

  Soft-delete = deactivate. Historical values retained; field drops from
  form-schema for new create/edit.


  After any create / edit / delete
  --------------------------------
  [ ] Invalidate / refetch Item form-schema cache
       GET .../entities/item/form-schema
  [ ] If Vendor module was also open in another tab, same for vendor
