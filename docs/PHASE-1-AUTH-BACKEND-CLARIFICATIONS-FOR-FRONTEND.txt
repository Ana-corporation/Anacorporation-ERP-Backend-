QUESTION 5 — x-company-id HEADER (P0)
------------------------------------------------------------------------------
WHAT FRONTEND NEEDS:
  Required on protected routes?

ANSWER:
  Choice: C — optional but recommended.

  - JWT cid (companyId) is the source of truth for tenant context.
  - If x-company-id header is sent, it MUST match JWT cid or HTTP 403.
  - If header omitted, tenant guard uses JWT companyId only.

  Frontend recommendation:
    Send x-company-id: activeCompanyId on all authenticated API calls
    (same value as JWT cid after login/switch).

QUESTION 6 — ERROR RESPONSE FOR FORM VALIDATION (P0)
------------------------------------------------------------------------------
WHAT FRONTEND NEEDS:
  Show field errors on login/signup forms.

ANSWER:
  Choice: C — Zod validation shape (not simple field/message pairs).

  HTTP 400 example (validation):
    {
      "success": false,
      "message": "Validation failed",
      "data": null,
      "errors": [
        {
          "code": "invalid_type",
          "path": ["employeeCode"],
          "message": "Invalid input: expected string, received undefined",
          "expected": "string"
        }
      ],
      "timestamp": "2026-07-10T06:00:00.000Z",
      "path": "/api/v1/auth/login"
    }

  Frontend mapping:
    field = error.path.join('.')     // e.g. "employeeCode"
    message = error.message

  Non-validation 400 (e.g. missing company):
    {
      "success": false,
      "message": "Company not found",
      "data": null,
      "timestamp": "...",
      "path": "/api/v1/auth/login"
    }

QUESTION 7 — ACCOUNT LOCKOUT RESPONSE (P0)
------------------------------------------------------------------------------
WHAT FRONTEND NEEDS:
  HTTP status and locked-until field for UI.

ANSWER:
  HTTP status for lockout:
    - 403 Forbidden — account locked until timestamp (policy lockout)
    - 401 Unauthorized — user.is_locked flag or wrong password

  Locked-until field name in response:
    NOT a separate JSON field in Phase 1.
    Message string contains ISO timestamp:
      "Account is locked until 2026-07-10T12:30:00.000Z"

  Example 403 JSON:
    {
      "success": false,
      "message": "Account is locked until 2026-07-10T12:30:00.000Z",
      "data": null,
      "timestamp": "...",
      "path": "/api/v1/auth/login"
    }

  Example 401 (locked user):
    {
      "success": false,
      "message": "Account is locked",
      "data": null,
      ...
    }

  Frontend: parse ISO from message with regex, or show message as-is.
  Future improvement: backend may add data.lockedUntil — not in Phase 1.

STATUS: [x] DONE
