================================================================================

WHAT WE NEED TO KNOW:
  What does the user type on the login screen to sign in?

OPTIONS (pick one or combine):
  A) username only          (users.username)
  B) email only             (users.email)
  C) username OR email      (single input field — server checks both)
  D) employee code only     (emp code — see note below)
  E) employee code OR email
  F) employee code OR username
  G) employee code OR username OR email   (single field — any match)

NOTE — EMPLOYEE CODE:
  Schema location (CONFIRMED for Phase 1):
    - user_companies.employee_id  (VARCHAR 40) — emp code per user PER company

  Also exists (not used for Phase 1 login):
    - users.username
    - users.email

  SaaS NOTE:
    Multi-login (username / email / emp code) is the LONG-TERM product goal so each
    tenant company can choose what they expect. Phase 1 starts with emp code only.
    Future: company-level login policy (e.g. company_security_policies or settings).

FRONTEND LOGIN FORM LABEL:
  What text shows on UI? (e.g. "Username", "Email", "Employee Code", "Emp ID")

API REQUEST FIELD NAME:
  What JSON key does frontend send?
  Examples:
    { "username": "..." }
    { "email": "..." }
    { "login": "..." }        // generic — server resolves type
    { "employeeCode": "..." }

CURRENT BACKEND (today):
  POST /api/v1/auth/login
  { "email": "user@company.com", "password": "...", "companyId": "1" }

ANSWER (AGREED 2026-07-06):
  Phase 1 NOW:     D) employee code only
  SaaS FUTURE:     G) employee code OR username OR email (company-configurable)

  Emp code stored: user_companies.employee_id (per company membership)

  API JSON field name (proposed): employeeCode
  Example request:
    { "employeeCode": "EMP-00123", "password": "********", "companyId": "1" }

  UI label (proposed): "Employee Code" or "Emp ID"

  OPEN SUB-QUESTION (needs answer for Question 3):
    Is employee_id unique GLOBALLY across all companies?
    OR unique only WITHIN one company (then companyId required at login)?
