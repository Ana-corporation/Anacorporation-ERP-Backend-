0. ONE-LINE SUMMARY
--------------------------------------------------------------------------------
  One shared PostgreSQL database.
  Every company is a ROW in `companies`.
  Every business record (vendor, role, custom field, …) has `company_id`.
  Login picks a company → JWT carries companyId → APIs filter by that company.

2. DATABASE MODEL (CURRENT)
--------------------------------------------------------------------------------

  NOT created per company:
    ✗ ANA_ERP_DB per tenant
    ✗ Separate migrate per tenant

  YES — shared tables, tenant column:

    companies
      company_id (PK)
      company_code (unique)   e.g. DEMO_ACME, PLATFORM
      name, status, …

    user_companies
      user_id + company_id
      employee_id             e.g. ADMIN001  (login code)

    roles / role_permissions
      scoped by company_id

    company_subscriptions / company_modules
      which plan/modules this company has

    vendors
      company_id + vendor_code

    custom_field_definitions
      company_id + entity_type + field_name

    custom_field_values
      company_id + entity_type + record_id + field_id


3. HOW A COMPANY GETS CREATED
--------------------------------------------------------------------------------

  PATH A — Public Signup — REMOVED (2026-08-13)
  ----------------------------------------
  POST /api/v1/auth/signup → 404 (route deleted)

  Replacement user entry:
    Company-admin invite → POST /companies/:companyId/users/invite
    Then login + change-password if mustChangePassword


  PATH B — Platform / Admin create company
  ----------------------------------------
  Platform/super-admin company provisioning OR
  POST /api/v1/companies

  Creates company ROW (+ audit).
  Admin user/roles may come from platform bootstrap or seed/invite after.


  PATH C — Seed (local/demo)

    DEMO_ACME / ADMIN001 / Admin@123  → ADMIN (full modules)
    DEMO_ACME / MGR001   / Manager@123
    DEMO_ACME / STAFF001 / Staff@123
    DEMO_ACME / SALES001 / Sales@123

  Also seeds:
    - Plan + CompanySubscription

    - Vendor custom field samples (DEMO_ACME)


4. LOGIN FLOW
--------------------------------------------------------------------------------

  1) Resolve company
       GET  /api/v1/auth/company?companyCode=DEMO_ACME
       or send companyCode on login

  2) Login
       POST /api/v1/auth/login
       {
         "companyCode": "DEMO_ACME",
         "employeeCode": "ADMIN001",
         "password": "Admin@123"
       }

  3) Backend checks
       - Company exists / not suspended / not cancelled
       - Membership: employeeCode under that company
       - Password + security policy (lockout)
       - Load role permissions + subscribed modules

  4) Response
       - accessToken (JWT) with companyId
       - user / companies / activeCompany snapshot for FE

  5) Later calls
       Authorization: Bearer <accessToken>
       Path: /api/v1/companies/{companyId}/vendors
       Optional header: x-company-id (must match JWT company)


5. REQUEST FLOW AFTER LOGIN (GUARDS)
--------------------------------------------------------------------------------

  Request
    → JwtAuthGuard          (valid token?)
    → TenantGuard           (company context? header match?)
    → PermissionsGuard      (custom_fields:*, companies:*, …)
    → ModulePermissionGuard (supply-chain:view, …)
    → Controller
    → Service / Repository  (WHERE company_id = ?)


6. SUBSCRIPTION + MODULES FLOW
--------------------------------------------------------------------------------

  SubscriptionPlan
       │
       ▼
  CompanySubscription   (this company is on which plan)
       │
       ▼
  CompanyModule / PlanModule
       │
       ▼
  At login: modules[] with actions (view/create/edit/…)
       │
       ▼
  Product APIs gated by @RequireModulePermission
    e.g. Vendors → supply-chain:view|create|edit|delete

  Admin APIs gated by @RequirePermissions
    e.g. custom_fields:create


7. VENDOR + CUSTOM FIELDS FLOW (CURRENT FEATURE)
--------------------------------------------------------------------------------

  Admin defines fields (company-scoped):
    POST /companies/{companyId}/custom-fields
      entityType = vendor
      sectionKey = general | payment | custom | …
      displayName → auto fieldName
    Stored in: custom_field_definitions

  Vendor form loads schema:
    GET /companies/{companyId}/entities/vendor/form-schema

  User saves vendor:
    POST /companies/{companyId}/vendors
    {
      "code": "V-1",
      "name": "...",
      "metadata": { ... SAP tabs ... },
      "customFields": { "vendorTier": "preferred" }
    }

  Storage:
    Standard columns + metadata  → table `vendors`
    customFields values          → table `custom_field_values`
                                   (record_id = vendor_id)

  List (optional):
    GET /vendors?includeCustomFields=true
    GET /vendors?cf.vendorTier=preferred
