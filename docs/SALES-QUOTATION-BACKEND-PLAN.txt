1. GLOBAL SAAS PRINCIPLES  [REQUIRED]
-------------------------------------
  1. Country-specific behaviour sits behind an INTERFACE or a SETTING.
     No country columns on core tables (pan, gstin, state_code) and no
     if (country === 'IN') branches in quotation code.
  2. Core tables hold generic data (tax identifiers, region, postal code,
     tax breakdown). Country rules live in providers and settings.
  3. Money precision comes from currency.decimal_places, never a hard-coded 2.
  4. Store UTC timestamps. valid_until is a company-local DATE, read in the
     company timezone.
  5. Error codes and enum values are English and fixed in DB and API.
     FE turns codes into text. Server-side translation is [LATER].
  6. India GST is the first TaxProvider, not the design.


2. RULES  [REQUIRED]
--------------------
- Server calculates totals, status and permissions. Ignore client totals.
- Prisma Decimal for money / qty. No JS float maths.
- Routes: companies/:companyId/... (global api/v1 prefix) +
  assertCompanyAccess + RequirePermissions.
- Sent / Accepted versions read-only. Changes = new revision.
- No hard delete after issue. Cancel = status + reason.
- Every PATCH / action takes rowVersion. Stale => 409 ROW_VERSION_CONFLICT.
- Status actions (issue, response, cancel) are safe to repeat: status check +
  rowVersion. If the quotation is already in the target status, return it
  unchanged (no second event).
- send-email needs an Idempotency-Key header (see 4.8). Same key = first
  result, no second email.
- A Sent quotation past valid_until cannot be accepted or issued again.
  Checked on read and on response, independent of the daily job.
- Numbers reserved from Number Series inside the same transaction
  (never count()+1).
- Multi-row writes (header + lines + status history + audit) in one
  transaction.
- Migrations: DEV (Erp_test_db) first, then LIVE (Ana_corporation_db) only
  with user approval. Every migration has a rollback note (down script or
  manual steps) and is reviewed before LIVE.

6.2 Services
  [REQUIRED] QuotationPricingService (pure functions, Decimal)
    Uses currency.decimal_places and the quotation's rounding_mode /
    rounding_stage. No hard-coded 2.
    line_gross = qty x unit_price
    discount_amount = line_gross x discount_percent / 100
    line_net = line_gross - discount_amount
    document discount allocated by line_net
    charges added            [LATER]
    tax = TaxProvider.calculate(...), honours prices_include_tax
          (inclusive: take tax out of the price; exclusive: add on top)
    rounding_adjustment, grand_total, grand_total_base
    cost / margin            [LATER] (columns exist)
    SECTION / TEXT / OPTIONAL lines are not counted in totals.
  [REQUIRED] TaxProvider interface
      calculate(lines, company, customer, addresses, pricesIncludeTax)
      -> per-line tax + tax_breakdown + header tax_total
    NoTaxProvider now. IndiaGstProvider in Phase 7. More countries = new
    providers, no schema change.
  [REQUIRED] QuotationsService: create, update, get, list, validate,
    duplicate, delete draft.
    On create: reserve number, version 1, copy company settings (rounding,
    tax inclusive, language), snapshot customer name / tax ids / addresses /
    item code + description.

11. PHASE 7 - TAX PROVIDERS  [REQUIRED for the go-live country]
---------------------------------------------------------------
  Generic part (all countries):
    tax_codes: id, company_id, country_code, scheme (GST, VAT, SALES_TAX ...),
      code, name, rate, effective_from, effective_to.
    item_tax_classifications: item_id, country_code, scheme_code
      (HSN / SAC / HS / commodity), code, tax_code_id, effective_from.
      (No hsn_sac_code column on the item.)
    Lines fill tax_code_id, tax_percent, tax_amount, tax_breakdown.
    Header returns tax_breakdown [{ name, rate, base, amount }].
  India (IndiaGstProvider, tax_provider_code = IN_GST):
    - tax_codes loaded from the official GST portal HSN/SAC Excel
      (no outside package / API at runtime).
    - Company state = companies.region_code (Phase 0); place of supply =
      customer ship-to (else bill-to) region_code.
    - CGST + SGST same state, IGST other state, rupee round-off, Decimal.
    - Breakdown names: CGST, SGST, IGST.
  Other countries later: new provider + tax_codes data only.
  No quotation table change (columns exist from Phase 2).


12. STATUS FLOW (server enforced)
---------------------------------
  DRAFT --submit--> PENDING_APPROVAL --approve--> APPROVED --issue--> SENT
  DRAFT --submit (no approval)--> APPROVED
  PENDING_APPROVAL --return--> DRAFT
  PENDING_APPROVAL --reject--> REJECTED
  SENT --accept--> ACCEPTED
  SENT --reject--> REJECTED (lost_reason)
  SENT --revision requested--> REVISED (old) + new DRAFT version
  SENT --valid_until passed--> EXPIRED
  DRAFT / APPROVED / SENT --cancel--> CANCELLED
