1. PRODUCT DECISIONS (LOCKED)
--------------------------------------------------------------------------------

  D1  Storage model
      Shared Neon DB + companyId (NOT database-per-company).
      Definitions in custom_field_definitions.
      Values in custom_field_values (NOT new columns on vendors).

  D2  Who creates fields
      Company ADMIN creates fields DIRECTLY.
      NO request / pending / approve / reject workflow (skipped).

  D3  Module scope now
      Vendor ONLY.
      Customer / Employee / Sales / … later — separate handoff.

  D4  Form UX goal
      Fields appear inside existing Vendor tabs/sections (sectionKey).
      Prefer one form feel — not a separate “Custom Fields” ghetto tab
      when sectionKey is set (e.g. general). Fallback section = custom.

  D5  metadata vs customFields
      Both supported forever (for now):
        metadata     = FE hardcoded SAP-style tabs
        customFields = dynamic admin-defined UDFs
      Do NOT put the same key in both.

  D6  Approval / Form Designer / Formula / Lookup / File
      Deferred. Not in current scope.

3. DATABASE TABLES
--------------------------------------------------------------------------------

  vendors
    Core columns + metadata JSON
    Table: vendors

  custom_field_definitions
    Field setup per company + entityType
    Columns include: field_name, display_name, field_type, section_key,
                     validation, options, is_required, is_filterable, …

  custom_field_values
    Answers per vendor record
    record_id = vendor_id
    Typed columns: value_text / value_number / value_date / value_bool / value_json

  NOT created:
    custom_field_requests
    custom_field_options (options stored as JSON on definition for v1)


4. API CONTRACT (VENDOR — STABLE)
--------------------------------------------------------------------------------

  Base: /api/v1
  Auth: Authorization: Bearer <accessToken>
  Tenant path: /companies/{companyId}/...

  --- Meta (Create UI dropdowns) ---
  GET  /custom-fields/meta/modules
  GET  /custom-fields/meta/modules/vendor/sections
       → { sections[], reservedFieldNames[], reservedDisplayNames[] }

  --- Definitions (Admin) ---
  GET    /companies/{companyId}/custom-fields?entityType=vendor
  GET    /companies/{companyId}/custom-fields?entityType=vendor&groupedBySection=true
  GET    /companies/{companyId}/custom-fields/{fieldId}
  POST   /companies/{companyId}/custom-fields
  PATCH  /companies/{companyId}/custom-fields/{fieldId}
  DELETE /companies/{companyId}/custom-fields/{fieldId}

  Create body (fieldName OPTIONAL — auto from displayName;
               sectionKey REQUIRED — catalog key from meta/sections):
  {
    "entityType": "vendor",
    "sectionKey": "general",
    "displayName": "Factory Capacity",
    "fieldType": "number",
    "isRequired": false,
    "sortOrder": 40,
    "isFilterable": true,
    "validation": { "min": 0, "max": 100000 },
    "options": null,
    "helpText": "optional"
  }

  Dropdown must include options: [{ "value", "label" }, ...]

  --- Vendor form ---
  GET  /companies/{companyId}/entities/vendor/form-schema
       fields[] include: fieldName, displayName, fieldType, sectionKey,
                         isRequired, defaultValue, validation, options,
                         isFilterable, placeholder, helpText, sortOrder

  GET    /companies/{companyId}/vendors/{id}
         → vendorCode + metadata? + customFields{...}
  POST   /companies/{companyId}/vendors
  PATCH  /companies/{companyId}/vendors/{id}
  GET    /companies/{companyId}/vendors?includeCustomFields=true
  GET    /companies/{companyId}/vendors?cf.vendorTier=preferred

  Create vendor request uses "code"; response uses "vendorCode".

7. VALIDATION / ERRORS
--------------------------------------------------------------------------------

  Unknown customFields key → 400
  Required missing → 400
  Reserved fieldName OR displayName (Vendor Name, GST Number, …) → 400
  Duplicate displayName/fieldName → 400 (reject; no auto-rename)
  Invalid sectionKey / missing sectionKey → 400
  Invalid defaultValue / validation rules → 400
  Dropdown invalid option → 400
  Soft-delete keeps values; Vendor GET still returns historical customFields
  Details: docs/CUSTOM-FIELDS-BACKEND-VALIDATION-ENHANCEMENTS.txt

  Error shape:
  {
    "success": false,
    "message": "...",
    "errors": [{ "field": "customFields.vendorTier", "message": "..." }],
    "data": null
  }

  PATCH customFields clear rules:
    omit key  → leave
    null / "" → clear (if not required)
    checkbox false → store false
