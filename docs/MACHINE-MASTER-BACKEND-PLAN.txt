1. DECISIONS
------------
- Separate Machine master; every machine is linked to exactly one Item
  Master item (created automatically) so stock, quotation, sales order and
  production keep using items.
- Base machine code = prefix (model), typed by the user: BS500, ZETA700.
- Customised machine code = base code + "-" + sales order number:
  BS500-SO00045 (SO + 5 digits). Generated by the backend, never typed.
- Until Sales Order exists, the order number is entered manually when the
  customised machine is created (same format SO + 5 digits).
- Linked item category = "Machines" (code MAC) in the Finished Goods store,
  set per company in machine settings (no hard-coded ids).
- No option suffixes (-P etc.) now.
- Revision = change for everyone (same code, new BOM version).
  Suffix    = change for one order (new code, own CUSTOMER BOM).


2. DATABASE  (prisma/manufacturing/machines.prisma)
---------------------------------------------------
Enums
  MachineType    BASE | ORDER                 @@map("machine_type")
  MachineStatus  ACTIVE | INACTIVE            @@map("machine_status")

machines
  machine_id BIGSERIAL PK, uuid, company_id FK
  machine_code VARCHAR(40)     BS500 / BS500-SO00045 (uppercase)
  name VARCHAR(200)            "BS500 Bag Sealing Machine"
  series VARCHAR(20)           BS, ZETA (optional, for filters)
  model VARCHAR(40)            500, 700 (optional)
  description TEXT, remarks TEXT
  image_file_asset_id UUID null (same pattern as items)
  machine_type machine_type default BASE
  status machine_status default ACTIVE
  item_id BIGINT FK items      linked item (NOT NULL, UNIQUE)
  base_machine_id BIGINT FK machines null   (ORDER type -> its BASE)
  sales_order_no VARCHAR(20) null           SO00045 (ORDER type)
  sales_order_id BIGINT null                filled when Sales Order exists
  customer_id BIGINT FK customers null
  created/updated/deleted by + at, row_version
  UNIQUE (company_id, machine_code)
  UNIQUE (item_id)
  UNIQUE partial (company_id, base_machine_id, sales_order_no)
         WHERE machine_type = 'ORDER' AND deleted_at IS NULL
  CHECK (machine_type = 'BASE' AND base_machine_id IS NULL AND sales_order_no IS NULL)
     OR (machine_type = 'ORDER' AND base_machine_id IS NOT NULL AND sales_order_no IS NOT NULL)
  CHECK machine_code ~ '^[A-Z0-9][A-Z0-9-]{0,39}$'
  INDEX (company_id, status), (company_id, base_machine_id), (company_id, customer_id)

machine_settings  (one row per company)
  company_id PK/FK, item_group_id FK item_groups (Machines category),
  uom_id FK uoms (default NOS), created/updated by + at
  -> where machine items are created; no ids hard-coded in code.

BOM (no new columns)
  boms.parent_item_id = machine.item_id (unchanged meaning)
  customised machine BOM: bom_scope = CUSTOMER, source_type = CUSTOMER_COPY,
  base_bom_id / base_version_no = the base machine's released BOM,
  customer_id, source_document_type = 'SALES_ORDER',
  customization_notes = remarks.

Migration: <ts>_machine_master, DEV first, LIVE with approval.
Rollback: DROP TABLE machine_settings, machines; DROP TYPE machine_type,
machine_status. Items created for machines stay (they are normal items).


3. LINKED ITEM (automatic)
--------------------------
On machine create (one transaction):
  - Item in machine_settings.item_group_id (its store), UOM from settings.
  - Part number from the ITEM number series (category MAC -> ANAMAC00001).
  - description = machine name; oldCode = machine code (searchable);
    status active; metadata { source: 'MACHINE', machineCode }.
  - If the company has the item custom fields: procurementType = Make,
    materialType = Finished Good, materialCategory = Mechanical (only the
    fields that exist; others skipped).
  - Name / status changes on the machine are copied to the item.
Existing item link: POST /machines with linkItemId (no new item) - used to
attach ANAASSY00012 to machine BS500 (item keeps its code ANAASSY00012).
Machine items are excluded from the component picker
(items/lookup?excludeMachines=true -> NOT item_id IN machines.item_id).


4. API  (/api/v1/companies/:companyId)
--------------------------------------
Machines
  GET    /machines                list: search (code, name, series), filters
                                  type (BASE|ORDER), status, baseMachineId,
                                  customerId; sort; rows incl. item code,
                                  current BOM no + status, variant count
  GET    /machines/lookup         light list for the BOM Machine dropdown:
                                  active machines (base + order), code, name,
                                  itemId, uom, currentBom
  GET    /machines/{id}           detail + linked item + BOMs + variants
  POST   /machines                create BASE: { machineCode, name, series?,
                                  model?, description?, remarks?, linkItemId? }
  PATCH  /machines/{id}           { rowVersion*, name, series, model,
                                  description, remarks, status }
                                  (machineCode and type are fixed)
  DELETE /machines/{id}           soft delete; blocked when it has a BOM or
                                  variants (MACHINE_IN_USE)
  POST   /machines/{id}/image     same as items
Customised machine
  POST   /machines/{id}/variants  Idempotency-Key
         { salesOrderNo*, customerId?, remarks? }
         -> creates ORDER machine BS500-SO00045 + its item + a CUSTOMER BOM
            DRAFT copied from the base machine's current RELEASED standard BOM
            (all groups, same Common Keys). If the base has no released BOM ->
            BASE_BOM_NOT_RELEASED (copy needs a released source).
         Response: machine detail + { bomId, bomNumber }.
  GET    /machines/{id}/variants  ORDER machines of a base
Settings
  GET/PUT /machine-settings       { itemGroupId, uomId }
BOM changes
  POST /boms accepts machineId (server sets parentItemId = machine.itemId);
  parentItemId still accepted (backward compatible).
  BOM detail / list add machine { machineId, machineCode, machineType,
  baseMachineCode } when the parent item belongs to a machine.
  POST /boms on an ORDER machine is not allowed directly (use /variants) ->
  MACHINE_VARIANT_BOM_VIA_VARIANT.
Items lookup
  excludeMachines=true (component picker); onlyMachines=true (fallback).


5. RULES AND ERROR CODES
------------------------
  MACHINE_NOT_FOUND 404 (also other company)
  MACHINE_CODE_EXISTS 409, MACHINE_CODE_INVALID 400 (A-Z, 0-9, '-')
  MACHINE_SETTINGS_MISSING 400 (no Machines category configured)
  MACHINE_IN_USE 409 (delete with BOMs / variants)
  SALES_ORDER_NO_INVALID 400 (must be SO + 5 digits)
  VARIANT_EXISTS 409 (same base + same order number)
  BASE_BOM_NOT_RELEASED 409
  VARIANT_OF_VARIANT 400 (only a BASE machine can be customised)
  ITEM_ALREADY_LINKED 409 (linkItemId used by another machine)
  ROW_VERSION_CONFLICT 409, IDEMPOTENCY_KEY_REQUIRED / _REUSED
  Field paths dot style (salesOrderNo, machineCode).


6. PERMISSIONS
--------------
  machines:view | machines:create | machines:edit | machines:delete
  (module manufacturing; alias manufacturing:{action}; ADMIN backfill;
  seed version bump). Creating a customised machine needs machines:create
  AND boms:create.

8. TESTS
--------
  - Create base machine -> item created in MAC (ANAMAC00001), oldCode = code.
  - Duplicate / invalid code rejected; other company -> MACHINE_NOT_FOUND.
  - Link existing item; same item twice -> ITEM_ALREADY_LINKED.
  - Variant: BS500 + SO00045 -> BS500-SO00045, item, CUSTOMER BOM DRAFT with
    the base BOM's groups and keys; base BOM untouched; same order twice ->
    VARIANT_EXISTS; idempotent retry creates once; base without released
    BOM -> BASE_BOM_NOT_RELEASED; variant of variant -> VARIANT_OF_VARIANT.
  - Customer BOM release does not clash with the base standard BOM.
  - Component picker excludes machine items.
  - Delete machine with BOM -> MACHINE_IN_USE.
