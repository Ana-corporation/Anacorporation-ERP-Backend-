                   MATCH  companyCode OPTIONAL — omit to auto-generate
                   MATCH  status optional; omit or send trial/active/suspended/cancelled

  409 duplicate:   MATCH  "Company code already exists"

================================================================================
CREATE COMPANY
================================================================================

  POST /api/v1/companies
  Permission: companies:create

  Recommended body (auto companyCode):

  {
    "name": "Acme Trading",
    "country": "India"
  }

  Response includes generated companyCode, e.g. "ACME_TRADING"
  (collision → ACME_TRADING_2; last resort → CO-000001)

  Optional manual code (backward compatible):

  {
    "name": "Acme Trading",
    "companyCode": "ACME",
    "country": "India",
    "status": "trial"
  }

  Still accepted if FE already sends them (backward compatible, not required):
    legalName, domain, email, phone, timezone, defaultCurrencyId


companyCode RULES
--------------------------------------------------------------------------------

  AUTO (preferred):
    Omit companyCode on POST.
    BE generates from name:
      "Acme Trading" → ACME_TRADING
      if taken → ACME_TRADING_2 …
      if still taken → CO-000001 (then CO-000002 …)
    Show the returned code as read-only after create.

  MANUAL (optional):
    If FE still sends companyCode:
      trim + uppercase, /^[A-Z0-9_-]+$/ max 30
      duplicate → 409

  After create: IMMUTABLE — do not PATCH companyCode.

  FE create form:
    Hide companyCode input OR show "Will be generated"
    After 200, display data.companyCode read-only


country
--------------------------------------------------------------------------------

  REQUIRED on create (new).
  Free text for now (e.g. "India") — no ISO country API in this phase.
  Editable later via PATCH.


status
--------------------------------------------------------------------------------

  Unchanged enum (do not rename):

    trial | active | suspended | cancelled

  Create: omit field OR send "trial" (default trial).
  FE dropdown: keep these four values.


Errors to handle
--------------------------------------------------------------------------------

  400  missing country
  400  invalid companyCode (format)
  400  companyCode cannot be changed   (if PATCH includes companyCode)
  409  Company code already exists
  403  missing companies:create / companies:edit

  Fixed 2026-09-01:
    POST /companies 400 "Invalid entityId" was a BE audit bug
    (SYSTEM role provision logged entityId="ADMIN" which is not numeric).
    Create company should return 200 after BE restart.

UPDATE COMPANY
================================================================================

  PATCH /api/v1/companies/{companyId}
  Permission: companies:edit

  NEW: country is allowed

  {
    "name": "Acme Trading Pte Ltd",
    "country": "Singapore"
  }

  Also still patchable:
    legalName, domain, email, phone, timezone, defaultCurrencyId, status

  DO NOT send companyCode on PATCH — BE rejects it.

  companyId and createdAt remain read-only in UI.


STATUS SHORTCUT
--------------------------------------------------------------------------------

  PATCH /api/v1/companies/{companyId}/status
  Permission: companies:edit   (guard, not roleCode)

  { "status": "active" }

  Platform Owner (platform_companies:edit) may set status on any company.
  Company editor without that permission: own company only.


================================================================================
INVITE FIRST COMPANY ADMIN
================================================================================

  After create, same endpoint as before:

  POST /api/v1/companies/{companyId}/users/invite
  Permission: users:create

  {
    "firstName": "Priya",
    "lastName": "Admin",
    "email": "priya@acme.example.com",
    "employeeId": "ADMIN001"
  }

  NEW: if roleId is omitted / null, BE assigns roleCode ADMIN automatically.

  FE may still pass roleId (ADMIN) — unchanged.
  Platform Owner Create flow can drop the role picker for "first admin".

  Response (MUST show in UI once — email is a stub, no password is mailed):

  {
    "user": { ... },
    "temporaryPassword": "Ab3$........",
    "employeeId": "ADMIN001",
    "companyCode": "ANA_MACHINERY_PVT"
  }

  Login is NOT email. It is:
    companyCode + employeeId (employee code) + password

  If employeeId was omitted, BE now auto-assigns ADMIN001, ADMIN002, ...

  Resend (preferred):
    POST /api/v1/companies/{companyId}/users/{userId}/resend-invite
    Permission: users:create  (platform_companies:edit aliases this)
    Returns temporaryPassword + employeeId + companyCode.

  Dedicated admins list:
    GET /api/v1/companies/{companyId}/admins

  Full FE contract:
    docs/FE-HANDOFF-COMPANY-ADMIN-INVITE-LOGIN.txt
