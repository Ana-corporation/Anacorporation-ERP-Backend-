  See: docs/FE-HANDOFF-FORM-CONFIG-FULL-WORKPLAN-STATUS.txt

APIs
--------------------------------------------------------------------------------

  GET    /api/v1/companies/{companyId}/form-configurations/item
  PUT    /api/v1/companies/{companyId}/form-configurations/item
  DELETE /api/v1/companies/{companyId}/form-configurations/item

  GET    /api/v1/companies/{companyId}/entities/item/form-schema
         → builtInFields[] + resolvedSections[]
         → legacy fields[] (custom only) + sections[] (tab meta)

  Errors (same as Vendor):
    INVALID_FIELD_KEY
    PROTECTED_FIELD_CANNOT_HIDE
    ENTITY_TYPE_NOT_SUPPORTED


PROTECTED (configurable=false — Locked)
--------------------------------------------------------------------------------

  itemCode, description, itemType, status,
  isInventoryItem, isSalesItem, isPurchaseItem


UNIQUE fieldKey RULE (bag collisions)
--------------------------------------------------------------------------------

  Column fields:  camelCase API name
                  e.g. barcode, unitPrice, preferredVendorId

  Bag fields:     store prefix required
                  e.g. purchase.weight, sales.weight, inventory.weight
                       purchase.taxGroup, sales.taxGroup
                       planning.leadTimeDays, production.phantomItem

  FE alias map: map (FE name + store) → BE fieldKey


SECTIONS (sectionKey)
--------------------------------------------------------------------------------

  header | general | classification | purchasing | sales |
  inventory | planning | production | remarks | custom


apiKey CONTRACT (examples)
--------------------------------------------------------------------------------

  itemCode              → itemCode
  barcode               → barcode
  purchase.weight       → purchase.weight   (PATCH body.purchase.weight)
  sales.taxPercent      → sales.taxPercent
  planning.leadTimeDays → planning.leadTimeDays


HIDDEN FIELD SAVE BEHAVIOR
--------------------------------------------------------------------------------

  metadata JSON bags. Omitting a hidden key from the UI does NOT clear DB values.
  Column fields omitted from PATCH are also left unchanged.
