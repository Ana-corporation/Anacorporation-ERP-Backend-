================================================================================

GOAL
--------------------------------------------------------------------------------
  Index:  one row per part → bins + serials summary + total qty
  Expand: same part’s lines → Bin + Qty + Serial
  Post:   stock by Part + Store + Bin; serials on document only


================================================================================
BACKEND — DONE (use now)
================================================================================

1) Opening Stock GET / create / update / post responses include partIndex
--------------------------------------------------------------------------------
  GET|POST|PUT|POST …/inventory/opening-stock[/:id|/post]

  New field on OPENING_STOCK document only:

  partIndex: [
    {
      itemId, partNumber, partName, uom,
      inventoryLocationId, locationCode, locationName,
      totalQuantity,          // "10.000000" string
      lineCount,
      lineIds: ["…", "…"],    // expand = filter lines by these ids
      bins: [{ storageBinId, binCode }],
      serialNumbers: ["123", "234"],
      serialCount
    }
  ]

  Flat `lines[]` unchanged — still the source of truth for PUT body.


2) Storage bins list (picker) — higher limit + natural sort
--------------------------------------------------------------------------------
  GET …/storage-bins?inventoryLocationId={els001Id}&limit=500&sortBy=binCode&sortOrder=asc

  - limit: default 20, **max 500** (was global max 200 — blocked full ELS list)
  - When filtered by store + sortBy=binCode: **natural order** A1-01 … A1-200
    (not string order where A1-100 appears before A1-20)
  - Default sort for this endpoint: binCode asc


3) Unchanged rules (still apply)
--------------------------------------------------------------------------------
  One line = one storageBinId + optional one serialNo
  Bin required when store binManagement = true
  No serial stock balances / no multi-bin on one line
